# Connector contracts

The connector layer (`omega_prime/prime/`) is the typed, versioned boundary
between the tool surface (registry dispatch → JSON) and the ported Prime
capability modules (`agent/rlm.py`, `learning/harness.py`, `agent/goals.py`,
`agent/autonomous.py`, `agent/messaging.py`). It is not an FFI bridge — the
merge architecture is a behavior port (see
[ADR 0001](adr/0001-prime-merge-architecture.md)).

## Adapters

| Module | Wraps | Request/response types |
| --- | --- | --- |
| `prime/rlm.py` | `RlmHost` / `NoRlmHost` | `SpawnRequest`, `CollectRequest`, `ProgressNoteRequest`, `ChildResultView` |
| `prime/harness.py` | `HarnessState` | `UpsertRequest`, `EntryView` |
| `prime/goals.py` | `PrimeGoalStore` | `SetGoalRequest`, `AccrueRequest`, `GoalStatusView` |
| `prime/autonomous.py` | `AutonomousDriver` | `StartRequest`, `VerdictView` |
| `prime/messaging.py` | `SessionRegistry` | `SendRequest`, `MessageView` |

## Rules every adapter enforces

1. **Versioned schemas.** Each adapter module carries `SCHEMA_VERSION = 1`.
   A payload may declare `schema_version`; `from_dict` rejects a version
   newer than the adapter's own with
   `PrimeError("unsupported_schema_version", ...)` — the forward-compat
   guard is loud, never silently last-good.
2. **Strict decoding.** Unknown fields are rejected (`unknown_field`);
   booleans never pass as integers and vice versa (`bad_type`); closed
   vocabularies (status sets, harness kinds/scopes, stop reasons) are
   enforced on both encode and decode (`bad_value`).
3. **Structured failures.** Every connector failure is a
   `PrimeError(code, reason)`; the wire shape is `"code: reason"`, matching
   the registry's `{"error": ...}` surface. A missing message recipient is
   `unknown_recipient` — structured, never a silent drop.
4. **Round-trip fidelity.** `from_dict(x.to_dict()) == x` for every request
   type; tool-surface JSON decodes back into typed views losslessly
   (pinned by `tests/test_prime_contracts.py`).
5. **Degrade-with-warning.** A capability that raises inside the loop is
   wrapped by `agent/degraded.py::guarded_hook`, which emits a structured
   `prime_degraded` event (family, error, turn id) and the loop continues
   without that family for the turn.

## Parity fixtures

`omega_prime/tests/parity/*.json` pin Prime behavior for the ported
surface — no-host error strings, progress-note cap/throttle, collect
timeout snapshots, goal token arithmetic, harness validation rejections,
and the closed status vocabularies — each fixture citing its upstream
source file. The fixtures are generated by reading the sources; the Rust
baseline's role as the executable oracle lives in CI (`rust-parity.yml`),
so hermetic Python tests never require a Rust toolchain.

# 63-01: Streamable HTTP transport

## Objective

Serve MCP Streamable HTTP at `/mcp` from the same host as legacy SSE, bounded and principal-bound, as a
standalone module the 63-08 integrator mounts. Do not edit `remote.py`.

## Change

Create `omega_prime/grokbot/streamable.py` per the contract in `63-CONTEXT.md`:

1. `build_streamable_http(server, *, security_settings=None, max_body_bytes=1_048_576, max_sessions=64,
   session_idle_timeout=1800.0, json_response=False) -> StreamableHttp` wrapping
   `mcp.server.streamable_http_manager.StreamableHTTPSessionManager(app=server, stateless=False,
   security_settings=..., max_request_body_size=max_body_bytes, max_sessions=..., session_idle_timeout=...,
   json_response=...)`. Read `mcp/server/streamable_http_manager.py` first: sessions are stateful, the SDK
   already enforces body size (413), the session cap (503 "Too many open sessions") and idle expiry (404).
2. The route is `Route("/mcp", endpoint, methods=["GET", "POST", "DELETE"])` where `endpoint` is an object with
   `async def __call__(self, scope, receive, send)` (a raw ASGI app, so Starlette does not wrap it as a
   request/response function; `/mcp` must not redirect to `/mcp/`). Before delegating to
   `manager.handle_request`, the endpoint copies our principal into the SDK's session-owner mechanism: if
   `principal_from_scope(scope)` (from `omega_prime.grokbot.security`) is not None, set
   `scope["user"] = AuthenticatedUser(AccessToken(token="principal:" + principal.id, client_id=principal.id,
   scopes=sorted(principal.scopes)))` using `mcp.server.auth.middleware.bearer_auth.AuthenticatedUser` and
   `mcp.server.auth.provider.AccessToken` (confirm the exact constructor fields in the SDK; the token string is a
   non-secret placeholder, never the bearer token). The SDK then answers 404 "Session not found" to a different
   principal presenting someone else's `Mcp-Session-Id`.
3. `StreamableHttp.lifespan()` returns `manager.run()` (an async context manager the host enters in its
   Starlette lifespan; entering it twice is an SDK error, so the integrator enters it once).
4. Module docstring explains the contract; SPDX header.

## Edge cases

- No principal (auth disabled on loopback): do not set `scope["user"]`; sessions are unowned (SDK behavior).
- A request arriving before `lifespan()` is entered gets the SDK's error; do not hide it.
- `/mcp` with other HTTP methods -> 405 from `Route`.

## Tests (hermetic, real socket)

Compose a tiny Starlette app in the test: a stand-in auth middleware class that reads
`Authorization: Bearer a|b` and sets `scope["state"]["principal"]` to `Principal("alice", {"read","call"})` or
`Principal("bob", ...)` (import `Principal` from `omega_prime.grokbot.security`), the `StreamableHttp.route`, and a
lifespan entering `lifespan()`; the MCP `Server` is `mcp.server.Server("t", version="1", on_list_tools=...,
on_call_tool=...)` with one tool. Run it with `uvicorn.Server` on `127.0.0.1` port 0 in a thread (same pattern as
`test_grokbot_e2e.py`: read the bound port from `server.servers[0].sockets[0].getsockname()`). With the SDK client
`mcp.client.streamable_http.streamable_http_client` (inspect its signature in `mcp/client/streamable_http.py`):
initialize + list tools + call tool as alice succeed; a raw `httpx` POST to `/mcp` with bob's header and alice's
`Mcp-Session-Id` gets 404; a body over `max_body_bytes` gets 413; more than `max_sessions` concurrent sessions gets
503; `GET /mcp` without a session id returns the SDK's 4xx rather than hanging; DELETE ends the session.

- No dependency on `remote.py`; importing the module has no side effects.

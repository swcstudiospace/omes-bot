# 63-04: Traffic protection

## Objective

Bound request rate, blunt token guessing, and stop hammering a failing upstream tool: standalone ASGI
middleware and tool-call interceptors the 63-08 integrator composes. Do not edit `remote.py`.

## Change

1. `omega_prime/grokbot/ratelimit.py` per the contract in `63-CONTEXT.md`:
   - `RateLimiter(per_key_per_minute, global_per_minute=0, *, burst=None, clock=time.monotonic)`: a token bucket
     per key (refill `per_key_per_minute / 60` per second, capacity `burst or per_key_per_minute`, LRU-capped to
     10_000 keys so memory is bounded) plus one optional global bucket. `acquire(key)` consumes one token from the
     key bucket and the global bucket atomically (do not consume from one when the other denies) and returns None
     when allowed or the seconds until a token is available (> 0). A value of 0 disables that tier. Thread-safe.
   - `RateLimitMiddleware(app, *, limiter, exempt_paths=("/healthz", "/readyz"), on_limited=None)`: pure ASGI;
     http scopes only; key = `principal.id` from `principal_from_scope` else the client host; denial is `429` JSON
     `{"error": "rate_limited", "retry_after": n}` with `Retry-After: ceil(n)`; `on_limited(event_dict)` receives
     `{"key", "path", "retry_after"}` (never headers or tokens) and its exceptions are swallowed.
   - `AuthFailureThrottle(max_failures, window_seconds=60.0, *, clock=time.monotonic)`: sliding window per client
     host (bounded memory); `record(client)`, `blocked(client) -> float | None` (seconds until the oldest counted
     failure leaves the window once `max_failures` is reached; None otherwise); `max_failures=0` disables.
   - `AuthThrottleMiddleware(app, *, throttle, exempt_paths=...)`: pure ASGI, placed BEFORE auth; answers 429 +
     `Retry-After` when `throttle.blocked(client)`; exposes `throttle.record` for the integrator to call from the
     auth `on_failure` hook.
   - `ToolRateLimitInterceptor(limiter)`: implements the `ToolCallInterceptor` protocol (`before` returns
     `ToolDenial("rate_limited", "...", retry_after)` using `principal.id` else `"local"`; `after` is a no-op).
2. `omega_prime/grokbot/resilience.py`:
   - `CircuitBreaker(failure_threshold=5, cooldown_seconds=30.0, *, jitter=0.2, half_open_max=1, clock=
     time.monotonic, rng=None)`: states `closed`, `open`, `half_open`; `allow() -> float | None` (None = proceed;
     else seconds until the next probe is allowed); `record_success()`, `record_failure()`; N consecutive
     failures open it for `cooldown * (1 +- jitter)`; after the cooldown the next `allow()` admits up to
     `half_open_max` probes; a probe success closes it, a probe failure re-opens with a fresh jittered cooldown;
     `state` property. `failure_threshold <= 0` means never opens.
   - `is_infrastructure_failure(error: str | None) -> bool`: True only for transient/upstream failures. Inspect how
     `omega_prime/tools/registry.py` reports a handler exception and the error prefixes tools emit
     (`upstream_error:` appears in 6 places; `not_configured:` 13; `invalid_name:` 1) and treat as infrastructure:
     `upstream_error:` prefix, handler exceptions as the registry reports them, and messages containing
     `timed out`, `timeout`, `connection refused`, `connection reset`, `temporarily unavailable`. NOT infrastructure:
     `not_configured:`, `invalid_name:`, `policy forbids`, approval refusals, `forbidden`, `rate_limited`,
     `circuit_open`, `unknown_field`, `bad_value`, validation errors.
   - `ToolCircuitBreakerInterceptor(*, failure_threshold=5, cooldown_seconds=30.0, jitter=0.2, clock=..., rng=None)`:
     one lazily created `CircuitBreaker` per tool name (bounded); `before` -> `ToolDenial("circuit_open", ...,
     retry_after)` when `allow()` denies; `after` records success when `outcome.status == "ok"`, failure when
     `outcome.is_error and is_infrastructure_failure(outcome.error)`, and ignores denials and caller errors
     (a half-open probe that ends in a caller error must release the probe slot without counting).
3. SPDX headers; docstrings state the bounded-memory guarantees.

## Edge cases

- Bursts: capacity allows `burst` immediate requests then refills smoothly.
- A tool that succeeds once in the middle of failures resets the consecutive count.
- Denied requests must not consume tokens from the other tier.
- Clock injection everywhere; no real sleeps in tests.

## Tests

probe limit, threshold 0, `is_infrastructure_failure` table covering every prefix above, interceptor behavior with
a real `run_tool_call` chain (success/failure/denial/caller-error outcomes).

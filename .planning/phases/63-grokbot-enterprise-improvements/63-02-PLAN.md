# 63-02: Scoped, rotatable credentials

## Objective

A hashed, scoped, expiring, revocable token file with a CLI, a store the auth layer can use unchanged, live
reload, and fail-closed behavior. Do not edit `security.py`.

## Change

Create `omega_prime/grokbot/tokens.py` per the contract in `63-CONTEXT.md`:

1. `TokenRecord` (frozen dataclass: `id`, `sha256`, `scopes: tuple[str, ...]`, `label`, `created_at`,
   `expires_at: str | None`, `revoked_at: str | None`; ISO-8601 UTC strings). File format
   `{"version": 1, "tokens": [...]}`. Scopes must be a non-empty subset of `security.SCOPES`.
2. `create_token(path, *, scopes, label="", ttl_days=None, clock=time.time) -> tuple[str, TokenRecord]`:
   plaintext from `security.generate_token()`; id `tok_` + 8 hex chars unique within the file; store only
   `hash_token(plaintext)`; write the whole file with `atomic_write_json` (0600) under an exclusive lock
   (`fcntl.flock` on a sibling `<name>.lock`, guarded import) so concurrent CLI calls do not lose updates.
   `list_tokens(path)` never returns plaintext. `revoke_token(path, token_id) -> bool` sets `revoked_at`
   (idempotent; unknown id -> False).
3. `FileTokenStore(TokenStore)`: `__init__(path, *, clock=time.time, reload_interval=1.0)`. `enabled` is True
   once a path is configured (even degraded or empty-of-valid-tokens, so a bad file never means "no auth").
   `verify(presented)` first refreshes when `reload_interval` has elapsed since the last `stat()` and the file's
   `(mtime_ns, size)` changed; then hashes the presented value and compares against EVERY non-revoked,
   non-expired record with `hmac.compare_digest`, returning a `Principal(id, frozenset(scopes), label)`.
   A missing, unreadable, corrupt or wrong-version file sets `degraded=True`, `degraded_reason` (never the file
   contents) and makes `verify` return None for everything (fail closed); a later good file clears it.
   `principals()` lists valid records' principals. Thread-safe.
4. `CompositeTokenStore(TokenStore)`: `__init__(stores)`, `enabled` if any store is, `verify` returns the first
   match across stores (still evaluating every store to keep timing flat), `principals()` concatenated.
5. CLI `main(argv=None) -> int` (`python -m omega_prime.grokbot.tokens`): `new --file F --scope S [--scope S ...]
   [--label L] [--ttl-days N]` prints the plaintext token ONCE on stdout plus the id on stderr, exit 0;
   `list --file F [--json]` prints id, scopes, label, created, expires, status (active/expired/revoked), never
   hashes in the table (JSON includes `sha256`? no: omit it); `revoke --file F ID` exit 0 or 1 when unknown.
   Invalid scope -> exit 2 with a message.
6. SPDX header; docstring states the format and the fail-closed rule.

## Edge cases

- Expiry boundary: a token is invalid when `clock() >= expires_at`.
- A file edited by hand to contain a plaintext field is not special-cased; only `sha256` is read.
- Two processes calling `new` at once both end up in the file.
- Presented token that is empty or None -> None without hashing errors.

## Tests (hermetic; injected clock; `reload_interval=0` where freshness is tested)

create/list/revoke round trip; plaintext never in the file (read the bytes, assert absent); file mode 0600;
scope validation; expiry via injected clock; reload after another process-style rewrite (write a new file with
`atomic_write_json` and assert verify sees it); revocation takes effect on the next verify without restart;
corrupt JSON and wrong version deny everyone and set `degraded_reason`, recovery clears it; deleted file denies;
composite precedence; CLI exit codes and that `new` prints the token exactly once; an `AuthMiddleware`
integration through `starlette.testclient.TestClient` where a token works, is revoked, then gets 401, and
the principal id/scopes reach the endpoint.

## Acceptance

- `FileTokenStore` works as the `store` of the existing `AuthMiddleware` with no change to `security.py`.
- `python -m omega_prime.grokbot.tokens new --file F --scope call` followed by `list` and `revoke` behaves as above.

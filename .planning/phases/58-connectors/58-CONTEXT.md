# Phase 58: Connector layer + parity suite - Context

**Gathered:** 2026-10-08
**Status:** Ready for planning
**Mode:** Autonomous

<domain>
## Phase Boundary

Put every ported Prime capability behind a typed, versioned Python
adapter — the "connectors" of the merge — and prove fidelity: contract
tests on both sides of each adapter, failure-injection tests, and
behavior-parity fixtures derived from the Rust baseline. In scope:
`omega_prime/prime/` (new package: typed adapters + schemas), contract
tests, failure-injection tests, parity fixtures + runner. Out of scope:
new capability behavior (55–57 own that), CI (54), docs (59).

</domain>

<decisions>
## Implementation Decisions

1. **What a connector is here.** The merge architecture is a behavior
   port, so a connector is not an FFI bridge — it is the typed boundary
   between the loop/tools and each ported capability module:
   `omega_prime/prime/{rlm,harness,goals,autonomous,messaging}.py`
   adapters, each exposing frozen dataclasses (the `rlm/__init__.py`
   dataclass precedent: `RLMSpawnHandle`, `RLMChildResult`, …) with a
   `SCHEMA_VERSION` constant and `to_dict`/`from_dict` validation that
   rejects unknown/mistyped fields exactly like Prime's payload decoders
   (bool/int confusion rejected, closed status sets).
2. **Versioned contracts.** Each adapter module carries
   `SCHEMA_VERSION = 1`; `from_dict` rejects a payload whose
   `schema_version` exceeds the adapter's own (forward-compat guard, the
   pa-models "unsupported future versions keep last-good silently"
   precedent made loud instead of silent).
3. **Failure injection.** Tests drive each adapter with: raising
   capability, timeout (collect-style), malformed payload, unknown
   status string — asserting structured `{"error": "code: reason"}`
   surfaces and that the loop continues (ties into LOOP-06's
   `prime_degraded` event).
4. **Parity fixtures.** `omega_prime/tests/parity/` — JSON fixtures
   capturing Prime behavior for the ported surface: spawn handle shapes,
   collect timeout snapshots, throttle accept/reject, no-host error
   strings, harness validation rejections, goal budget arithmetic
   (`goal_token_delta_for_usage` cases), status vocabulary sets. Fixtures
   are generated by reading the Rust/Python sources (documented per
   fixture with the source file:line), not by running the Rust binary —
   the Rust baseline's role is the CI oracle (Phase 54); hermetic Python
   tests must not require a Rust toolchain.
5. **Both-sides contract tests.** "Both sides" in the port architecture:
   the tool surface (registry dispatch → JSON) and the capability surface
   (adapter → module). Contract tests pin that tool JSON round-trips
   through the adapter types losslessly.

</decisions>

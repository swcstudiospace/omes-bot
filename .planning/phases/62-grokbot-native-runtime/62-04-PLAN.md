# 62-04: Supervisor and lifecycle fixes

## Objective

Fix defect D-15: a supervisor an operator or systemd can trust. `--stop` must stop the supervisor and its
child; a hung server must be restarted by health probing; the restart budget must reset after stable
uptime; giving up must exit non-zero; state must be written atomically.

## Change

Rewrite `omega_prime/grokbot/supervisor.py` keeping the existing public names
(`SupervisorStatus`, `GrokBotSupervisor`, `main`) and adding:

1. `GrokBotSupervisor(command, state_file=None, max_restarts=5, backoff_base_sec=1.0, *,
   backoff_max_sec=30.0, stable_after_sec=60.0, health_url=None, health_interval_sec=5.0,
   health_timeout_sec=2.0, health_failures=3, health_start_period_sec=10.0, stop_grace_sec=10.0,
   clock=time.monotonic, sleep=time.sleep)` - the injected `clock`/`sleep` make timing testable.
2. Child process: `subprocess.Popen(command, start_new_session=True)` so the child has its own process group and a
   terminal Ctrl-C reaches only the supervisor. Stop a child with `os.killpg(pgid, SIGTERM)`, wait
   `stop_grace_sec`, then `SIGKILL` the group; tolerate `ProcessLookupError`.
3. `SupervisorStatus` keeps its current fields and gains `supervisor_pid: int | None`, `child_pid: int | None`,
   `healthy: bool | None`, `started_at: str | None`. `pid` stays as an alias of the child pid for compatibility.
   `uptime_seconds` is the CURRENT child's uptime (reset on each start).
4. `run_loop(poll_interval_sec=0.5) -> int`: returns 0 after a requested stop, 1 after exceeding
   `max_restarts` (with `last_error="Exceeded maximum restarts (N)"`). Backoff is
   `min(backoff_max_sec, backoff_base_sec * 2 ** (restarts - 1))` with +-10% jitter (deterministic when a
   `random.Random(seed)` is injected - add an optional `rng` kwarg). If the child ran at least
   `stable_after_sec` before dying, reset the restart counter to 0 first (a flaky-but-long-lived server is not
   a crash loop). Install SIGINT/SIGTERM handlers only when running on the main thread; the handler only sets
   the stop event (no `sys.exit` inside a handler), and the loop performs the orderly shutdown and final
   state write. A second signal forces an immediate SIGKILL of the child group.
5. Health probing: when `health_url` is set, after `health_start_period_sec` probe `GET health_url` every
   `health_interval_sec` with `urllib.request.urlopen(timeout=health_timeout_sec)`; HTTP 200 is healthy,
   anything else or an exception is a failure; `health_failures` consecutive failures kill the child group and
   count as a restart (reason recorded in `last_error`, e.g. "health check failed 3x").
6. State file (`.planning/grokbot_supervisor.json` default; written with `atomic_write_json` from
   `omega_prime/grokbot/_io.py`) holds the status dict including `supervisor_pid`. Write on start, every
   restart, every health transition, and on exit.
7. CLI `main(argv=None) -> int` (parse `argv`, default `sys.argv[1:]`): `--state-file`, `--max-restarts`,
   `--health-url`, `--health-interval`, `--stable-after`, `--stop-grace`, `--status`, `--stop`, and the
   command after `--` (or positional). Default command when none is given:
   `[sys.executable, "-m", "omega_prime.mcp_server", "--transport", "sse"]` (the stdio server exits without
   a client, so it is the wrong thing to supervise). `--status` prints the state JSON (or
   `{"running": false, "status": "no_state_file"}`) and returns 0. `--stop` reads `supervisor_pid`, checks it
   is alive (`os.kill(pid, 0)`), sends SIGTERM to the SUPERVISOR, polls up to `stop_grace + 5` seconds for it
   to exit, prints the outcome, returns 0 when it stopped and 1 when it was not running or did not stop.
   `if __name__ == "__main__": raise SystemExit(main())`.
8. SPDX header; docstring matches behavior.

## Edge cases

- Child exits 0 on its own: treat as an exit (restart) unless a stop was requested.
- State file unreadable/corrupt for `--status`/`--stop`: report and return non-zero rather than raising.
- `--stop` when the PID in the file is stale (process gone): print "not running", return 1.
- `run_loop` must not leave zombie processes: always `wait()` the child after killing it.

## Tests (hermetic; children are `[sys.executable, "-c", "..."]`)

Keep the existing supervisor test. Add: crash then restart increments `restarts` and uses the injected sleep
for backoff; restart counter resets after a stable run (injected clock); exceeding `max_restarts` makes
`run_loop` return 1 with `last_error`; status shows child and supervisor pid and current-child uptime;
health probing against a throwaway `http.server` thread (200 then 500) kills and restarts the child;
`--stop` end to end: start `python -m omega_prime.grokbot.supervisor --state-file F -- python -c
"import time; time.sleep(60)"` as a real subprocess, wait for the state file to show a child, call
`main(["--stop", "--state-file", F])`, assert it returns 0, the supervisor exited and the child pid is gone;
state file is valid JSON at every observation (atomic); `--status` on a missing file.

## Acceptance

- The old test still passes; the new ones pass without real sleeps longer than ~2 seconds.
- After `--stop`, neither the supervisor nor the child process remains.

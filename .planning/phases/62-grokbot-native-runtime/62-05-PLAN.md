# 62-05: Remote host - fail-closed transport, health/readiness, graceful shutdown, real-transport E2E

## Objective

Fix D-01..D-10: compose the 62-01 security core, the 62-02 audit log and the SDK's own transport
security into one ASGI app; make startup fail closed; make health truthful; drain gracefully; and prove
it with an MCP client over a real socket.

## Depends on

62-01 (`security.py`, `interceptors.py`, `mcp_server.load_runtime`, `call_tool_handler(..., interceptors,
transport)`), 62-02 (`GrokBotAuditTracer`, `default_audit_path`). Read those files first.

## Change

1. Rewrite `omega_prime/grokbot/remote.py` to the contract in `62-CONTEXT.md` (`create_sse_app`,
   `serve_sse`, `create_mcp_sse_app` alias). Behavior:
   - Startup (inside `create_sse_app`, before anything is served; raise, never swallow):
     resolve the token store (`token_store` argument, else `TokenStore.from_token(token)` when `token` is
     set, else none); `check_bind_safety(host, auth_enabled=store.enabled, allow_insecure=...)`;
     `load_runtime(root, home, no_roster=..., approvals=..., env=env)` (an invalid policy/roster is a
     `RuntimeConfigError`, never `policy = None`); create or accept the audit tracer
     (`GrokBotAuditTracer(default_audit_path(root))`); build interceptors in this order:
     `InFlightInterceptor`, `ScopeInterceptor`, `AuditInterceptor(audit)`, then the caller's `interceptors`.
   - Transport security: `TransportSecuritySettings(enable_dns_rebinding_protection=...,
     allowed_hosts=[...], allowed_origins=[...])` from `mcp.server.transport_security`, passed to
     `SseServerTransport("/messages/", security_settings=..., max_request_body_size=max_body_bytes)`.
     Allowed hosts: `127.0.0.1:*`, `localhost:*`, `[::1]:*`, the bind `host:port` when it is not a wildcard,
     the `public_url` hostname with and without `:*`, plus `allowed_hosts`. Allowed origins: `allowed_origins`
     plus the `public_url` origin. Protection is ON for a loopback bind and whenever `public_url` or
     `allowed_hosts` is configured; for a non-loopback bind with auth and neither configured, Host
     validation is OFF (bearer auth is the control; log one startup line saying so) but Origin validation
     stays on.
   - Middleware, outermost first: `CORSMiddleware` ONLY when there are allowed origins
     (`allow_origins=list`, methods GET/POST/OPTIONS/DELETE, headers `Authorization, Content-Type,
     Mcp-Session-Id, Last-Event-ID`, no wildcard, no credentials); then `AuthMiddleware` (only when the
     store is enabled; `on_failure` writes an `auth_failure` audit event with reason/path/client, never the
     token). No `BaseHTTPMiddleware` anywhere. The CORS stack is added exactly once.
   - Routes: `/healthz` (public): `status`, `service`, `version` (= `SERVER_VERSION`), `package_version`,
     `rostered_tools` (= `len(runtime.tool_names)`), `auth` ("required" | "disabled").
     `/readyz` (public): `ready` and `checks` {`registry`, `roster`, `policy`, `audit`, `shutdown`};
     HTTP 200 when ready, 503 when not (audit directory not writable, or `app.state.shutting_down`).
     `/sse` GET (SSE stream via `SseServerTransport.connect_sse`; keep passing `request.scope`,
     `request.receive`, `request._send`) and `Mount("/messages", app=sse.handle_post_message)`.
     Build the MCP server with `build_server(runtime.registry, runtime.roster, interceptors=..., transport="sse")`.
   - Lifespan: log one line on startup ("Omega Prime MCP host ready ..."); on shutdown flush/close the audit.
   - Tool execution: build ONE `ToolGate()` (from `omega_prime.mcp_server`, already implemented) per app, pass it
     as `gate=` to `build_server` and expose it as `app.state.gate`. Tool calls then run in a worker thread, one at
     a time, so a slow tool never freezes `/healthz`, `/readyz`, SSE keepalives or shutdown, and `in_flight.count`
     is meaningful for draining. Interceptors run in that worker thread, so they must be thread-safe.
   - `app.state`: `runtime`, `tool_names`, `audit`, `in_flight`, `gate`, `shutting_down`.
   - `serve_sse(...)`: catches `SecurityConfigError`/`RuntimeConfigError`/`ValueError` from construction,
     prints `omega-prime-mcp-server: <message>` to stderr and returns 2. Runs uvicorn through a small
     `uvicorn.Server` subclass (`GracefulServer`): on the FIRST SIGTERM/SIGINT set
     `app.state.shutting_down = True` (so `/readyz` goes 503), wait until `in_flight.count == 0` or
     `shutdown_grace` seconds elapse, then set `should_exit`; a SECOND signal sets `force_exit`. Pass
     `timeout_graceful_shutdown=max(1, int(shutdown_grace))`, `log_level="info"`. The startup banner must
     not print the token and must say whether auth is required.
2. Edit `omega_prime/mcp_server.py` `main()` and its argparse ONLY (the 62-01 library part stays):
   - Add flags per `62-CONTEXT.md`: `--public-url`, `--allow-host` (append), `--allow-origin` (append),
     `--token-env` (default `MCP_AUTH_TOKEN`), `--token-file`, `--token` (stderr warning that argv is visible
     to other users; still honored), `--allow-insecure-no-auth`, `--audit-log` (default from env
     `OMEGA_PRIME_AUDIT_LOG`), `--max-body-bytes`, `--shutdown-grace`.
   - Token resolution order: `--token-file` (via `read_secret_file`), `--token`, `os.environ[token_env]`;
     none -> no auth. Any `ValueError`/`SecurityConfigError` -> `omega-prime-mcp-server: <msg>` on stderr,
     return 2.
   - Parse `--approve TOOL:APPROVER` for BOTH transports into `(tool, approver)` pairs before branching
     (D-08); a malformed item keeps today's message and exit 2; the stdio path uses `load_runtime` and
     keeps today's stderr wording for roster/policy failures ("cannot read roster ...", "cannot load seat
     policy: ..."), exit 2. `asyncio.run(_serve(build_server(runtime.registry, runtime.roster)))` stays the
     stdio server.
3. SPDX header on remote.py; docstrings match behavior.

## Edge cases

- `TestClient` sends `Host: testserver`; tests that use it pass `allowed_hosts=["testserver"]`.
- Policy file missing -> `RuntimeConfigError` -> exit 2 (today's stdio behavior), both transports.
- `host="0.0.0.0"` + token -> allowed; + no token -> `SecurityConfigError` unless `allow_insecure_no_auth`.
- `public_url` with a path (`https://x.example/bot`) -> origin/host only; mount paths are not supported.
- The audit log must record `auth_failure` and `tool_call` events with no token text anywhere in the file.

- New `test_grokbot_e2e.py`: a fixture starts the app on `127.0.0.1` port 0 with

  thread, waits for `server.started`, reads the bound port from `server.servers[0].sockets[0].getsockname()`,
  and shuts it down at teardown. With the SDK client (`mcp.client.sse.sse_client` with an `Authorization`
  header, `mcp.client.ClientSession`/`Client`; inspect `mcp/client/` for the v2 API): (a) no header ->
  connection refused with 401; (b) authenticated initialize -> `list_tools` names equal `/healthz`
  `rostered_tools` count and `app.state.tool_names`; (c) call a harmless read-only tool (e.g. `todo_read`)
  -> success and one `tool_call` audit record carrying the principal id `env-token`, `ok` status, arg keys
  and no argument values, and `verify_integrity()` is True; (d) calling a tool absent from the roster ->
  error result and a `denied`/`error` audit record; (e) an approval-gated tool without approval -> error
  result, with approval (`approvals=[(tool, "tester")]`) -> not an approval error; (f) hostile `Origin`
  -> rejected; (g) the audit file contains no token text; (h) responsiveness: create the app with `no_roster=True`, register a
  test tool on `app.state.runtime.registry` that blocks on a `threading.Event` (with a 5 s wait timeout), call it
  through the MCP client in a background task, and while it is in flight assert `GET /healthz` and `/readyz`
  answer within 1 s and `app.state.in_flight.count == 1`; releasing the event lets the call finish and the count
  returns to 0; (i) drain: with `in_flight` forced above zero, the first shutdown request flips
  `app.state.shutting_down` (so `/readyz` is 503) but does not stop the server until the count drops to 0 or
  `shutdown_grace` elapses (use a tiny grace); a second request forces exit. Test this on the `GracefulServer`
  logic directly (no real signals needed: call its signal handler method). Keep each test under a few seconds.

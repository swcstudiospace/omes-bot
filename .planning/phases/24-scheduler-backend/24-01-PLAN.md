## Task 1: scheduler backend

### `omes/cron/apscheduler_backend.py` (new)

`SchedulerService(store, runner, *, scheduler=None, clock=time.time)`:

- `start()` runs one immediate `tick` for overdue jobs, then registers one
  APScheduler entry per incomplete job with `due_at` in the future: date
  trigger at `due_at` for one-shots, interval trigger every
  `interval_seconds` starting at `due_at` for intervals (UTC-aware).
  Returns the rows the immediate tick ran. Starting twice registers nothing
  twice (entries keyed by job id).
- Each fire calls `store.tick(clock(), runner)` — the whole cron semantic,
  so overlapping fires stay safe under tick's claim/history rules.
- `stop(wait=True)` shuts the scheduler down; stopping an unstarted service
  is a no-op. `job_ids` lists registered entry ids.
- `runner(prompt) -> str` is caller-supplied (same seam as `tick`).

### `omes/tests/test_apscheduler_backend.py` (new)

Real `BackgroundScheduler`, short horizons, poll-with-deadline waits:

- A one-shot fires once, completes, and persists `last_result` to the file.
- An interval job fires at least twice and advances `due_at`.
- Two one-shots sharing a due date each run exactly once.
- Restart: stop, rebuild the service on the same file, start — history is
  preserved and the interval job fires again without duplicates.
- Overdue jobs run on `start()` without waiting for a trigger.
- Double `start()` registers each job once; `stop()` before `start()` is safe.

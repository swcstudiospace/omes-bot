# Plan 22-01: SDK session client and dependency

## Goal

Call real MCP servers that require the initialize handshake, through the
official MCP Python SDK, beside the one-shot `mcp_call` (which stays for
servers that answer a single `tools/call` line). Same safety contract:
argv list only, cwd must exist, timeout kills the child.

## Starting Point

`omes/tools/mcp_client.py` spawns `command` and writes one `tools/call`

## Task 1: session client

### `omes/tools/mcp_session.py` (new)

`mcp_session_call(command, tool, arguments, *, cwd, timeout=5) -> dict`:

- Validation identical to `mcp_call`: argv list of non-empty strings (a plain
  string is refused), non-empty tool name, arguments dict, positive timeout,
  cwd is a directory. Same error strings where the case matches.
- Runs `stdio_client` + `initialize()` + `call_tool(tool, arguments)` under
  `asyncio.run` with an overall `asyncio.wait_for` timeout. Success returns
  `{"result": <model_dump(mode="json")>}`. A tool result with `isError`
  returns `{"error": <first text block or fallback>, "result": <dump>}`.
  SDK failures, timeouts, and spawn failures return `{"error": ...}` naming
  the stage (spawn, initialize, call, timeout).
- Timeout expiry cancels the session; the stdio client's close path reaps
  the child (asserted in tests via the fixture's pid file).

### `omes/tests/test_mcp_session.py` (new)

Fixtures are Python scripts written to `tmp_path` (no fixture files in the
tree). A scripted server answers `initialize` (echoing the requested
protocol version), ignores `notifications/initialized`, and answers
`tools/call` from a canned map; a hanging variant sleeps past the timeout
and records its pid:

- initialize + call returns the canned content blocks as JSON-safe data.
- `isError` results return both `error` and `result`.
- String command, empty argv, blank tool, non-dict arguments, bad timeout,
  and missing cwd are all refused without spawning anything.
- Missing executable returns a spawn error (no traceback leak).
- Hanging server: timeout error names the timeout and the pid is reaped.

# Plan 15-01: Turn journal, cron history, and checkpointed workflows

## Goal

Every journaled turn lands in SQLite row by row, so a crashed turn resumes with its transcript intact. Cron jobs record bounded execution history and never re-run a completed tick. Multi-step workflows checkpoint between steps and resume from the last checkpoint. No journal attached means today's behavior.

## Task 1: Journal, history, checkpoints

### `omes/durable/journal.py` (new package `omes/durable/`)

`TurnJournal(path)` over SQLite (one connection per call, commits each write):

- Tables: `runs(run_id TEXT PRIMARY KEY, status TEXT, final_response TEXT)`, `rows(run_id TEXT, seq INTEGER, row TEXT, PRIMARY KEY (run_id, seq))`.
- `begin_run(run_id)`: insert `status='open'` (`INSERT OR IGNORE`; an existing run keeps its rows and status).
- `append(run_id, row: dict)`: store the next seq (`max+1`, starting at 0) as JSON (`default=str` for odd values). Unknown run ids are created as `open` first.
- `finish_run(run_id, status, final_response="")`: set status and response.
- `transcript(run_id) -> list[dict]`: rows in seq order (`[]` for unknown runs).
- `open_runs() -> list[str]`: run ids with `status='open'`, in first-row order.

### `omes/agent/conversation_loop.py`

`Agent` gains `journal: Any = None` and `run_id: str | None = None`. When `journal` is set: default `run_id` to a fresh hex id when None, `begin_run` at turn start, journal every newly appended row wherever a `message` event is emitted, and `finish_run` with the result's exit reason and final response. `journal=None` journals nothing and changes nothing.

### `omes/cron/scheduler.py`

Jobs gain `history` (list of `{"ran_at", "result"}`, newest last, capped at `HISTORY_LIMIT = 20`) and `claimed_at` (default None). Old stores backfill both on load.

`tick` order per due job: skip when `completed`, when `due_at > now`, when `claimed_at == now` (already claimed this tick), or when history already holds `ran_at == now` (completed this tick). Otherwise set `claimed_at = now` and save, run the runner, then append history (evicting past the cap), clear the claim, advance or complete as today, and save. A second `tick` at the same `now` runs nothing.

### `omes/durable/workflows.py` (new)

JSON checkpoints under `{directory}/workflows/{workflow_id}.json` (atomic write; id rule as session persist).

- `run_workflow(directory, workflow_id, steps, state=None)`: run each `step(state) -> state` in order from the checkpoint when one exists (steps already recorded as done are not re-run); after each step, checkpoint `{"done": index+1, "state"}`. Return `{"workflow_id", "state", "done": True}`. A step raising leaves the last checkpoint in place and propagates.
- `load_checkpoint(directory, workflow_id) -> dict | None`: the checkpoint or None.
- States must be JSON-serializable dicts; anything else is a `ValueError` before any step runs.

## Task 1: Contract, five adapters, install-surface check

### `omega_prime/providers/` (new package)

`base.py`:

- `Transport` protocol: `post(url: str, headers: dict, body: dict) -> dict`.
- `Provider` dataclass: `name`, `base_url`, `env_vars: tuple`, `api_mode`. Abstract `build_request(model, messages, tools, api_key) -> (url, headers, body)` and `parse_response(payload) -> dict` (an assistant row: `{"role": "assistant", "content", "tool_calls"?, "finish_reason"?}`).
- `ProviderError(RuntimeError)`: transport failures and unparseable payloads.
- `ProviderModel`: `__init__(provider, model, transport, api_key="")`; `complete(messages, tools=None) -> dict` satisfies the turn loop's `Model` protocol. A missing required key raises `ProviderError` before the transport is touched (the fake transport in tests never needs a real key, but the key parameter must be non-blank when the provider requires one — tests pass `"fake-key"`).

`fake.py`: `FakeTransport(post_fn=None)`: records `(url, headers, body)` per call in `calls`; returns `post_fn(...)` or the next scripted payload from `script`. An empty script raises `ProviderError`.

Adapters (each a `Provider` subclass with its endpoint, headers, and both directions mapped):

- `grok.py`: `GrokProvider`, base `https://api.x.ai/v1`, `POST {base}/chat/completions`, `Authorization: Bearer`, OpenAI-compatible bodies. Env `XAI_API_KEY`.
- `openai.py`: `OpenAIProvider`, base `https://api.openai.com/v1`, same chat-completions shape. Env `OPENAI_API_KEY`.
- `anthropic.py`: `AnthropicProvider`, base `https://api.anthropic.com`, `POST {base}/v1/messages` with `x-api-key` and `anthropic-version: 2023-06-01`. System rows become `system`; tool rows become `tool_result` blocks; `tool_use` blocks parse back to `tool_calls`. Env `ANTHROPIC_API_KEY`.
- `gemini.py`: `GeminiProvider`, base `https://generativelanguage.googleapis.com/v1beta`, `POST {base}/models/{model}:generateContent` with `x-goog-api-key`. Roles map user/model; `functionCall`/`functionResponse` parts round-trip tool calls. Env `GEMINI_API_KEY` (also accept `GOOGLE_API_KEY`).
- `ollama.py`: `OllamaProvider`, base `http://localhost:11434`, `POST {base}/api/chat`, `stream: False`, no key required. Env `()`.

Message mapping shared rules: `content` None becomes `""`; unknown row roles pass through untouched for OpenAI-compatible wires; tool rows carry `tool_call_id` when present. A response without usable content raises `ProviderError` naming the provider.

### Tests in `omega_prime/tests/test_providers.py`

1. A `ProviderModel` over `FakeTransport` scripted with one assistant text completes a `run_conversation` turn end to end; the transport saw one POST to the Grok chat-completions URL with a Bearer header.
2. The Grok adapter maps a tool-call response (OpenAI wire shape) to the loop's `tool_calls` row, and a missing key raises before the transport is touched.
3. Each of the OpenAI, Anthropic, Gemini, and Ollama adapters answers one scripted `complete` through `FakeTransport`: the URL, auth header (or none for Ollama), and parsed assistant row (including one tool round-trip per adapter) match the wire shape above.

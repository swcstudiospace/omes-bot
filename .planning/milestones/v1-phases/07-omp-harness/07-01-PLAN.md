# Plan 07-01: Merge the Omp agent-core behavior into the conversation loop

## Goal

One turn emits `turn_start`, per-row `message`, and `turn_end` events; a `before_model` hook can mutate the outgoing request or stop the turn before it is billed. Pause parks the loop at both action boundaries without aborting in-flight work, and steer text injected mid-turn lands as its own user row. A tool result flagged `useless` is never an error, errors are never useless, and an output budget stops a runaway turn before another model call. The phase 2 prompt, steer, compression, and interrupt checks still pass.

## Task 1: Wire the harness into the loop

### `omega_prime/agent/conversation_loop.py`

`Agent` gains four optional fields with `None` defaults: `before_model`, `pause_gate`, `output_budget`, `speculative_tools`. Existing constructors stay valid. `agent.events` stays a plain list created on first emit (see `harness.events_of`); it is not a dataclass field.

`_run_conversation_turn` changes, in this order:

1. Emit `turn_start` once, before the user row is appended. Emit one `message` event per row appended during the turn by snapshotting `len(messages)` around each append site (tool round, text finish, finalizer close) and emitting for the new slice. Emit `turn_end` with `turn_exit_reason` after `finalize_turn` returns. A turn with no hook, no gate, and no budget emits exactly `turn_start`, one `message` per appended row, `turn_end`.
2. Wrap `agent.tools` with `harness.wrap_tools` at turn start; restore the original in a `finally` around the whole turn so the caller's tool map is identical afterwards.
3. At the top of each iteration, before the interrupt check: if `agent.pause_gate` is set, `wait_until_resumed(agent.interrupt)`. A `False` return ends the turn as `interrupted_by_user` without consuming budget.
4. Run `harness.run_before_model(agent, messages, agent.tools)` after the budget consume and before `model.complete`. A stop decision ends the turn with that decision's reason (default `stopped_before_model`) without calling the model. The hook may mutate `messages` in place; the mutation is what the model sees.
5. Before each `run_tool_round`, fold `harness.drain_steer(agent)` into `agent.pending_steer` (queued entries first, then the legacy slot, joined) so the round delivers the steer as its own user row. Do not edit `turn_tool_round.py`.
6. Before each `run_tool_round`, when `agent.speculative_tools` is set, call `harness.prepare_speculative(agent, original_tools, tool_calls)` with the unwrapped tool map and the pending calls. After the round, call `harness.apply_tool_marks(agent, messages, since)` where `since` is the length before the round.
7. Charge output: after each model answer, `harness.account_output(agent, assistant_content)`; after each tool round, `harness.account_output(agent, *new_tool_contents)`. When accounting reports over budget, end the turn with `output_budget_exceeded` before another model call. No `output_budget` means no cap.
8. Before `finalize_turn`, move `harness.take_leftover_steer(agent)` into `agent.pending_steer` (joined with any legacy leftover) so the existing `pending_steer` result key reports undelivered steer.

### Tests in `omega_prime/tests/test_harness.py`

Use the fake-model style of `test_loop.py` (a `Model` stub returning scripted dicts). No real threads except where the test needs them (pause, mid-turn steer).

1. A text turn emits `turn_start`, then one `message` per appended row in order, then `turn_end` carrying the exit reason. `agent.tools` is the identical map object after the turn.
2. A `before_model` hook that appends a user row changes what the stub model receives. A hook returning `{"stop": True, "reason": "halt"}` ends the turn with no model call and no budget spent.
3. With the gate paused from another thread, the loop parks before the model call: no model call lands while paused, resume lets the turn finish, and in-flight tool work is not aborted. Interrupting a parked wait ends the turn while the gate stays paused.
4. `inject_steer` from another thread mid-turn lands as its own `{"role": "user"}` row after the tool row, never merged into tool content. The legacy `pending_steer` slot still delivers the same way.
5. A tool returning `{"content": ..., "useless": True}` persists a tool row with `useless is True` and `is_error is not True`. A tool returning `{"content": ..., "useless": True, "is_error": True}` persists an error row with no `useless` flag. `compress_messages` blanks the useless row with the notice and leaves the error row's bytes alone.
6. A stub model that always emits one more tool call trips a small `OutputBudget` and the turn ends `output_budget_exceeded` with no further model call after the trip.
7. A discard-safe tool pre-executes once and its result is committed on fingerprint match (handler runs once total). A changed argument discards the prepared entry and the handler runs fresh.
8. Undelivered queued steer is reported on the result's `pending_steer` key and the queue is empty after the turn.

### `omes/agent/delegate.py`

`delegate_task(parent, goal, *, tasks=None, max_depth=2, max_children=1, background=False) -> str`

Returns JSON.

- `parent` is the existing `Agent`. `parent.tools` is the tool map. `getattr(parent, "delegate_depth", 0)` is the depth.
- One `goal` is one task. `tasks` is a list of `{"goal": ...}` mappings. A batch longer than `max_children` returns an error and runs no child.
- When `delegate_depth >= max_depth`, return an error and run no child.
- The child gets `delegate_depth + 1`, its own `ScriptedModel` is not invented here: the caller passes `parent.child_model`, a `Model`, used only for the child. The parent model is not called for the child.
- The child message list starts empty except the goal as the user message. `run_conversation` on the child must not append to `parent`'s messages.
- The value returned to the parent is the child's `final_response` and nothing else. Child tool messages, tool names, and tool results stay on the child transcript.
- The child tool map is a shallow copy of `parent.tools`. After `delegate_task` returns, `parent.tools` is the same dict with the same keys and the same callable objects as before the call.
- Role: `orchestrator` when `child_depth < max_depth`, otherwise `leaf`. An orchestrator child's copy includes `delegate_task`. A leaf child's copy does not. The parent map is not edited to add or remove `delegate_task`.
- `background=False` runs the child before returning, and the JSON `summary` is the child's `final_response`.
- `background=True` returns JSON with `pending: true` and a `handle` before the parent has the summary. `join_delegate(handle)` runs the child if it has not run and returns the summary. Joining twice returns the same summary and does not run the child again.

### `omes/cron/scheduler.py`

`JobStore(path)` persists jobs in a JSON file.

- `schedule(prompt, due_at, *, interval_seconds=None) -> str` stores a job and returns its id. `due_at` is a unix timestamp in seconds.
- `tick(now, runner) -> list[dict]` runs each job with `due_at <= now` that has not been completed. `runner(prompt) -> str` is called once per due job. The job's `last_result` becomes that string and `last_ran_at` becomes `now`. When `interval_seconds` is set, `due_at` becomes `now + interval_seconds`. Otherwise the job is complete and a later tick does not run it.
- A job with `due_at > now` is left unchanged.
- `run_due_jobs(store, now, model, tools) -> list[dict]` is the default runner wiring: for each due job it calls `run_conversation` on a new `Agent(model=model, tools=tools)` with the job prompt as the user message, and stores `final_response`.

### Tests in `omes/tests/test_delegate.py`

1. A parent `run_conversation` whose model calls `delegate_task` ends with the child's `final_response` in the parent tool row. The child's tool result is a unique string `child-tool-marker`. That string is absent from the parent `messages`. The child's tool name is absent from the parent messages.
2. `id(parent.tools)` and the key-to-callable mapping are equal before and after `delegate_task`. The child popping a key from its own map does not remove it from the parent.
3. `max_depth=1` lets the parent spawn one child. That child's tool map has no `delegate_task`. A direct `delegate_task` on an agent whose `delegate_depth` is already 1 returns an error and does not call the child model. `max_children=1` with two tasks returns an error and calls the child model zero times.
4. `background=True` returns `pending: true` without the summary. `join_delegate` returns the summary. A second join does not call the child model again.
5. A job due at `now` runs through `run_conversation` and `last_result` is the model's text. A job due later is not run. A one-shot job does not run on the next tick. A job with `interval_seconds` is due again at `now + interval_seconds`.

## Goal

The agent reads mentions and posts, publishes posts and threads, and stages media through five registry tools. Publishing requires approval; reads do not. Credentials resolve through the broker per endpoint, and every test runs behind a fake transport — no live X calls.

## Starting Point

`Transport.post` is the only seam; X reads need GET, so the protocol, `FakeTransport`, and `HttpTransport` each gain `get(url, headers, params)`. The registry's `requires_approval` gate plus `ApprovalLog` is the publishing control. Brokered auth follows the provider shape: a tiny provider record (`name="x"`, `env_vars=("X_API_TOKEN",)`).

## Task 1: X connector family

### `omes/providers/base.py`, `fake.py`, `http.py`

`Transport` gains `get(url, headers, params) -> dict`. `FakeTransport.get` records `(url, headers, params)` in `calls` (same list, in order) and replays the script. `HttpTransport.get` builds the query string, enforces the host allowlist, and shares the retry/timeout/error rules with `post` (refactor the common path; no behavior change for POST).

### `omes/tools/x.py` (new)

`XError(RuntimeError)` carrying the API's `title`/`detail`/first error message.

`XClient(base_url="https://api.x.com", upload_url="https://upload.twitter.com", transport, credentials=None, token="")` (`credentials(url) -> str` wins over `token`; no credential at all raises `XError` before any transport call):

- `me() -> {"id", "name", "username"}` from `GET /2/users/me`.
- `mentions(user_id=None, max_results=10, pagination_token=None) -> {"posts": [...], "next_token"?}` (`user_id=None` resolves via `me()`; `max_results` 1–100 or `ValueError`).
- `read_post(post_id) -> {"id", "text", ...}` from `GET /2/tweets/:id`.
- `post(text, reply_to=None, media_ids=None) -> {"id", "text"}` (`text` non-blank or `ValueError`).
- `thread(texts, reply_to=None) -> [{"id", "text"}, ...]` chaining `in_reply_to_tweet_id` (non-empty list of non-blank texts or `ValueError`; an empty list posts nothing).
- `upload_media(data: bytes, mime="image/png") -> {"media_id"}` (bytes, non-empty, at most 5 MiB; posts a form field set the fake transport can observe).

Non-2xx transport failures surface as `XError` naming the endpoint and the API message when present.

`X_TOOL_NAMES = ("x_mentions", "x_read_post", "x_post", "x_post_thread", "x_upload_media")`.

`register_x_tools(registry, client)`:

- `x_mentions(user_id=None, max_results=10)` → `{"posts", "next_token"?}`.
- `x_read_post(post_id)` → the post.
- `x_post(text, reply_to=None, media_ids=None)` → `{"id", "text"}`, `requires_approval=True`.
- `x_post_thread(texts, reply_to=None)` → `{"posts": [...]}`, `requires_approval=True`.
- `x_upload_media(data_b64, mime="image/png")` → `{"media_id"}` (invalid base64 is an error that calls nothing).
- `XError` becomes `{"error": ...}`; approvals use the registry's existing gate.

### Tests in `omes/tests/test_x.py`

A scripted `FakeTransport` plus a broker over `{"X_API_TOKEN": "x-secret"}` (tests assert the Bearer header without embedding a real credential).

1. `x_mentions` resolves the user id via `me` and returns two fixture posts with a next token; `x_read_post` returns one post. No approval needed.
2. `x_post` without approval returns the approval error and the transport sees nothing; with approval it POSTs `{"text", "reply"?, "media"?}` and returns the id. `x_post_thread` chains three posts with `in_reply_to_tweet_id` and returns three ids.
3. `x_upload_media` stages bytes and returns the media id; invalid base64 errors without a transport call.
4. An API error payload surfaces as `{"error": ...}` naming the message. An unapproved host gets no credential (broker refusal, transport untouched).
5. Plan mode refuses `x_post` while `x_mentions` still dispatches (handler-level check via `apply_plan_mode`).

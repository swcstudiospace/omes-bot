# Plan 52-01: Chunked answers + eval growth + truthful docs

**Phase:** 52 (DPT-04, EVAL-01, EVAL-02)
**Mode:** Resume interrupted execution; apply reviewed corrections before gates.

## Findings (probed against the repo)

- The initial implementation retains a raw `retrieval` branch beside chunks.
  Review CR-01 traces that raw data through registry, MCP, and model consumers.
- Lead reference (`LeadClient.docs_search`): per-chunk
  `content|document|dataset_id|score`, `redact_text` + 1500-char cap,
  non-dict entries skipped.
- RAGflow bodies carry `code` + `data.chunks` with vendor key spellings
  (`document_keyword`, `similarity`, ...); chunks may embed secrets.
- Eval runner reads only `golden.json` + `redteam.json` (23 cases);
  `adversarial.json` is PyRIT-keyed only. Registry cases can pin the new
  `ult_session_mark` approval behavior; `*_UNAPPROVED` pattern per family.
- Truth: roster YAML = 109 tools, MCP-served (no delegate) = 108.
  Per-family counts in build-aesthetics still hold; the +5 vs 104 is the
  substrate family, which user-guide/build-aesthetics never mention.

## Design

- **DPT-04**: `docs_search` returns only extracted chunks with typed,
  bounded, recursively redacted metadata and explicit citation provenance.
  No arbitrary raw payload escapes. Non-zero RAGflow codes, transport/plane
  failures, and malformed successful envelopes return bounded, redacted errors.
  Nested/top-level chunk lists and genuine empty lists remain supported.
- **EVAL-01**: approved/unapproved `ult_session_mark` cases use real
  ultrathink registration with an injected runner; approval comes from the
  production contract. Empty allow-lists remain deny-by-default.
- **EVAL-02**: setup/user-guide/build-aesthetics 104 → 109 (+ substrate
  mention where families are listed); tool-host 103 → 108. Remove brittle
  test/eval totals from prose and regenerate the corrected tool catalog.

## Tests

- Replace obsolete raw-preservation assertions with whole-result redaction,
  content bounds, safe provenance, and actual MCP boundary regressions.
- Distinguish malformed successful responses from legitimate empty results.
- Exercise approved/refused mark behavior; removing production mark approval
  must make the red-team eval fail. Remove incidental case-count/ID pins.
- Remove inherited configuration/source-spelling/heading proxies; prove lint,
  types, MCP behavior, catalog freshness, navigation, and controlled Discord
  failure using the actual consumers and executable gates.

## Verification

- Regenerate the tool catalog after the corrected retrieval description;

- Independent re-review, phase verification, Nyquist coverage, and security

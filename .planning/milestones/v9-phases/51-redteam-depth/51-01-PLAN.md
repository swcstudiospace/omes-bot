# Plan 51-01: Isolation + orchestrator campaigns + scorer judging

**Phase:** 51 (DPT-01, DPT-02, DPT-03)
**Mode:** Inline (no planner/executor agents in this runtime)

## Findings (probed against installed PyRIT 1.1.0)

- Import-time write comes from `pyrit/common/path.py` (`mkdir` + `LOG touch`)
  via appdirs `user_data_dir`; `XDG_DATA_HOME` redirects it (verified).
  Only `test_pyrit_target.py` + `pyrit_target.py` import pyrit.
- `MultiPromptSendingAttack(objective_target=..., attack_scoring_config=...)`
  runs scripted multi-turn attacks keyless; needs `supports_multi_turn`
  capability + `objective` + `Message` user_messages; result carries
  outcome/turns/last_score; turns readable from memory by conversation_id.
- `SubStringScorer.score_async(Message)` → `[Score]`, `.get_value() -> bool`;
  default match is case-insensitive — judging uses case-sensitive to match
  battery semantics.
- Multi-turn accumulation would break JSON dispatch, so the target answers
  the latest turn (single-turn behavior identical).

## Design

- **DPT-01**: `omega_prime/tests/conftest.py` sets `XDG_DATA_HOME` (setdefault) into
  tmp before any pyrit import; tests assert the mechanism + (Linux) that
  `DB_DATA_PATH` lives under it. macOS note: appdirs ignores XDG there
  (writes to ~/Library, writable but untidy).
- **Target**: `OmegaPrimePromptTarget` declares multi-turn capability; responds to
  the latest message's pieces.
- **DPT-02/03**: `run_campaign(target, objective, turns, objective_substring?)`
  drives one `MultiPromptSendingAttack`, pairs turns from memory, judges each
  response with case-sensitive `SubStringScorer`s per `must_contain` /
  `must_not_contain`, returns `{objective, outcome, turns, verdict}`.
- Campaigns (inline, deterministic): approval/policy state chaining across
  turns; cross-turn injection resistance; objective-scorer outcome marking.

# 62-06: 1-click launcher, doctor, emulator

Three file-disjoint units that can be implemented in parallel (each owns its module and its test file).
They depend on the finished 62-03 manifest/lint API and the 62-05 remote host contract
(`serve_sse` keyword arguments, `mcp_server` flags, `load_runtime`, `call_tool_handler`).

## Unit A - `oneclick.py` (D-13)

Keep `run_oneclick(...)` and `main(argv)` callable with today's arguments; add keyword arguments.

- Flags: `--root`, `--transport {stdio,sse}`, `--host`, `--port`, `--public-url`, `--export-manifest PATH`,
  `--token-env NAME` (default `MCP_AUTH_TOKEN`), `--token-file PATH`, `--token T` (stderr warning that argv
  is visible), `--generate-token`, `--allow-origin` (append), `--allow-host` (append), `--audit-log PATH`,
  `--allow-insecure-no-auth`, `--strict/--no-strict` (default strict for `sse`, off for `stdio`),
  `--skip-doctor`, `--dry-run`, `--json`.
- Token resolution as in 62-05 (file, argv, env). `--generate-token` (sse only, only when no token was
  resolved): `generate_token()` from `security.py`, print it ONCE to stderr with a one-line instruction to put
  it in the Grok Bot connector settings and store it with `--token-file`, export it to the server through
  the environment variable named by `--token-env` for this process only; when `--token-file` is also given and
  does not exist, write the token there with `atomic_write_text` (mode 0600) instead of printing it twice.
- Preflight: `run_doctor_checks(root, port, host=host, auth_enabled=<bool>)` (new keyword arguments, see
  Unit B). A `fail` check aborts with exit code 3 under `--strict` (print each failure with its fix hint);
  warnings never abort. `--no-strict` keeps today's continue-with-warning behavior. `--skip-doctor` skips it.
- Bind safety is evaluated before anything is written or served: `check_bind_safety(host, auth_enabled=...,
  allow_insecure=...)`; a `SecurityConfigError` prints its message and exits 2, also under `--dry-run`.
- Manifest export: `generate_manifest(root, transport=..., public_url=..., host_url=<derived>,
  auth_enabled=..., token_env=...)`; the SSE URL comes from `--public-url` when given, else
  `http://<host or 127.0.0.1 for wildcard>:<port>/sse`; written with `atomic_write_text` mode 0o644; never the
  token.
- `--dry-run`: preflight + bind safety + manifest export, then exit 0 without serving. `--json` prints one
  JSON object (`passed`, `strict`, `checks`, `transport`, `url`, `manifest_path`, `auth`) on stdout and sends
  human text to stderr.
- Serving: stdio -> `subprocess.call([sys.executable, "-m", "omega_prime.mcp_server", "--root", str(root)])`
  (pass `--audit-log` through when set); sse -> `serve_sse(root=..., host=..., port=..., token=<resolved>,
  public_url=..., allowed_hosts=..., allowed_origins=..., allow_insecure_no_auth=..., audit=None or a tracer for
  --audit-log)`. Return its exit code.
- Tests: dry-run stdio and sse (existing assertions stay valid: `http://127.0.0.1:59125/sse`, bearer auth,
  manifest_version), `--public-url` wins, wildcard host rewritten, strict abort with exit 3 when a doctor check
  fails (monkeypatch `run_doctor_checks` to return a failing check), `--no-strict` continues, bind-safety
  exit 2 for `0.0.0.0` without a token and ok with `--allow-insecure-no-auth`, `--generate-token` prints a token
  once and writes a 0600 token file, the token never appears in the exported manifest or in stdout `--json`,
  argv `--token` emits the warning.

## Unit B - `doctor.py` (D-14)

Keep `GrokBotDoctor`, `DiagnosticCheck`, `run_doctor_checks`, the existing check ids and the JSON shape
(`passed`, `checks[{id,name,category,status ok|warn|fail,message,fix_hint}]`). Extend
`GrokBotDoctor.run_all_checks(check_port=8000, *, host="127.0.0.1", auth_enabled=False)` and
`run_doctor_checks(root=None, port=8000, *, host="127.0.0.1", auth_enabled=False)`. Add checks (ids in
parentheses): seat policy loads (`policy_loads`; FAIL with the exception text); roster loads and every
roster name is registered or is a known flag-gated Prime family tool (`roster_consistency`; WARN listing
at most 10 unregistered names); template lint (`template_integrity`; FAIL when `bot.integrity` has missing
items); audit chain (`audit_chain`; verify the existing log with `GrokBotAuditTracer.verify_integrity`;
FAIL when broken, PASS when absent/empty); bind exposure (`bind_exposure`; FAIL when `host` is not loopback
and `auth_enabled` is False, PASS otherwise); token strength (`token_strength`; looks at the env var
`MCP_AUTH_TOKEN` when set: WARN under 32 characters, never print the value); connector secrets report
(`connector_secrets`; PASS with the NAMES of configured connector env vars among `XAI_API_KEY`,
`X_API_TOKEN`, `TELEGRAM_BOT_TOKEN`, `DISCORD_BOT_TOKEN`, `SUBSTRATE_TOKEN`, `HINDSIGHT_API_KEY`, never their
values). The port check binds the configured `host` (wildcards bind as such), uses a context-managed socket,
and keeps WARN when the port is taken. The manifest check uses the new manifest and reports tool and
approval-gated counts. Update `main()` flags (`--host`, `--auth`, `--json`, `--strict`): exit 1 on any FAIL;
with `--strict`, also exit 1 on any WARN. Tests: every new check id appears; `policy_loads` FAIL for a corrupt
copied tree; `bind_exposure` matrix; token strength never leaks the value (assert the secret is absent from the
JSON); `connector_secrets` lists names only; port check honors `host`; existing two tests stay green.

## Unit C - `emulator.py` (D-17)

Keep `GrokBotTurnEmulator`, `TurnResult`, `execute_tool`, `run_smoke_suite`, `main`. Build the emulator on the
production runtime: `load_runtime(root, home, no_roster=False, approvals=...)` and drive tool calls through
`call_tool_handler(runtime.registry, runtime.roster, interceptors=[ScopeInterceptor(), AuditInterceptor(
auditor)], transport="stdio")` (it is async: run it with `asyncio.run` per call or keep one loop), using a
tiny fake context object whose `request.state.principal` is a `Principal("emulator", {"read","call"})`, so
roster, policy, approval gates, scopes and audit behave exactly like the remote host. `execute_tool` keeps
returning `{"status", "result", "elapsed_ms"}` / `{"status": "error", "error": ...}`; a tool outside the roster
or not registered is `status="error"` (use the public registry API, never `registry._tools`). Default `root`
is `find_repo_root()`, not cwd. Add `approvals` and `auditor` constructor arguments, an `--approve
TOOL:APPROVER` flag, and a smoke scenario that proves an approval-gated tool is refused without approval and
passes the gate with it (pick a gated tool from `runtime.gated_tools` and an argument payload the gate
rejects BEFORE running the tool body, so the scenario never performs a real side effect; if no safe such tool
exists, assert only the refusal). Tests: keep the three existing tests valid; add roster-denial and the
approval scenario; assert audit records are written with caller `emulator`.

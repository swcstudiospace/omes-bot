# 62-02: Tamper-evident audit log

## Objective

Make `GrokBotAuditTracer` a real enterprise audit sink: hash-chained records, size rotation with chain
continuity, private file modes, multi-thread and multi-process safe appends, O(1) tail reads, a verifier
that names the first bad line, and a small CLI.

## Change

Rewrite `omega_prime/grokbot/audit.py` keeping every existing public name working
(`redact_sensitive`, `sanitize_payload`, `GrokBotAuditTracer(log_path=None)`, `.log_path`, `.log_event`,
`.read_recent`, `.verify_integrity() -> tuple[bool, int, str]`) and implementing the contract in
`62-CONTEXT.md`:

1. Record format and hash: `seq` (starts at 1, +1 per record), `timestamp` (UTC ISO), `event`, `tool_name`,
   `caller`, `status`, `duration_ms`, `is_error`, `details` (sanitized), `prev`, `hash`.
   `hash = sha256((prev + canonical_json(record_without_hash)).encode()).hexdigest()`; genesis
   `prev = "0" * 64`. After rotation the first record of the new file continues `seq` and `prev` from the
   last record of the rotated file.
2. Appending: take a `threading.Lock` and, when `fcntl` is importable, an exclusive `fcntl.flock` on the
   file for the whole read-tail / compute / append / flush sequence, so several processes continue one
   chain. Under the lock read the last complete line of the active file (seek back from the end in blocks;
   never read the whole file) to get `seq` and `hash`; when the file is empty or absent and a rotated
   predecessor exists, continue from the predecessor's last record. Write exactly one `\n`-terminated line
   per record; `fsync` is not required per record but `close()` flushes. New files are created with mode
   0o600 (`os.open(..., 0o600)`); a log directory this call creates is 0o700 (`ensure_private_dir` from
   `omega_prime/grokbot/_io.py`).
3. Rotation: before appending, if the active file size >= `max_bytes`, shift `audit.jsonl.N -> N+1` (drop
   beyond `backups`), rename the active file to `.1`, and start a new active file whose first record carries
   the chain forward. Do it under the same lock so two writers never rotate twice.
4. `verify_integrity(include_rotated=False)`: parse each line; require valid JSON, ascending `seq` by 1,
   `prev` equal to the previous record's `hash` (the first record of the active file is accepted as the
   chain start when it is the oldest available file, i.e. `prev` need not be genesis after old backups were
   dropped, but within the file it must chain), and a recomputed `hash` that matches. Return
   `(False, count_ok, "line N: <reason>")` for the first failure with reasons `invalid JSON`,
   `hash mismatch (record modified)`, `prev mismatch (record removed or reordered)`, `seq gap`;
   `(True, count, "verified N audit records")` otherwise; a missing log -> `(True, 0, "log does not exist yet")`.
   With `include_rotated=True` verify oldest-to-newest across `.N ... .1`, active as one chain. Legacy lines
   without `hash` are reported as `line N: missing hash`.
5. `read_recent(limit)`: tail only the last `limit` complete lines (block read from the end), skip blank or
   invalid lines.
6. Redaction: keep the current patterns and add JWT-like `eyJ...` triplets, `omk_` generated tokens,
   `Authorization`/`Cookie` header values; key-based redaction also covers `authorization`, `cookie`,
   `bearer`, `credential`. Keep `sanitize_payload` recursive and non-mutating.
7. `default_audit_path(root)`; `main(argv)` with `verify [--path P] [--all]` (exit 0 ok / 1 broken, prints
   the verifier message) and `tail [--path P] [-n N]` (prints JSON lines); `python -m omega_prime.grokbot.audit`
   works (`if __name__ == "__main__": raise SystemExit(main())`).
8. Add the SPDX header and update the module docstring so it matches the behavior.

## Edge cases

- Concurrent writers from 8 threads: all records present, chain valid, no duplicate `seq`.
- A torn or corrupt last line (crash mid-write): `verify_integrity` reports it and `read_recent` still
  returns the valid lines. The next `log_event` must not extend a corrupt tail silently and must not stop
  auditing: under the lock it renames the active file to `<name>.corrupt-<UTC YYYYmmddTHHMMSSZ>` (kept, never
  deleted), starts a new active file whose first record is `event="audit_chain_reset"` with
  `details={"quarantined": "<filename>", "reason": "<what was wrong>"}` and `prev` = hash of the last VALID
  record of the quarantined file (genesis when there is none), then appends the requested record.
- `details` containing non-JSON-serializable values: stored via `default=str`.
- The log path's parent is created on first use, not at import.

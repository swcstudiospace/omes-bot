# 62-03: Truthful manifest, template lint, drift sync

## Objective

Fix D-12 and D-16. The manifest Grok Bot imports must describe exactly what the host serves and never
embed a secret; `sync --check` must report drift only when content Grok Bot would see has changed.

## Depends on

62-01: `omega_prime.mcp_server.load_runtime` / `Runtime` (served and gated tool names).

## Change

1. `manifest.py` (keep `find_repo_root`, `parse_template_sections`, `get_assembled_prompt`,
   `generate_manifest`, `generate_grokbot_manifest`, `main`, existing keys `manifest_version`, `bot`,
   `mcp_server`, `capabilities`):
   - `served_tools(root, home=None, env=None) -> tuple[list[str], list[str]]` via `load_runtime`
     (roster enforced, policy applied). If `load_runtime` raises `RuntimeConfigError`, let the generator
     raise it (the doctor reports it); do not fall back to the static roster.
   - `generate_manifest` per the contract: `mcp_server.tools` = served names, `rostered_tool_count` =
     `len(tools)`, `approval_required` = gated names, `endpoints` for transport `sse`
     (`sse` = the URL given, `healthz`/`readyz` derived from the same origin), `auth` =
     `{"type": "bearer" if (auth_enabled if auth_enabled is not None else bool(auth_token)) else "none",
     "token_env": token_env or None, "scopes": ["read", "call"]}`; the token value is never written
     (a test must grep the serialized manifest for the token string).
   - URL rules: when `public_url` is given the SSE URL is `public_url.rstrip("/") + "/sse"`; otherwise
     `host_url`; a URL whose host is `0.0.0.0`, `::` or empty is rewritten to `127.0.0.1` and flagged with
     `mcp_server.url_note = "wildcard bind rewritten to loopback; pass --public-url for remote clients"`.
   - `bot.version` = `omega_prime.mcp_server.SERVER_VERSION` plus `bot.package_version` =
     `omega_prime.__version__`; `capabilities`: keep `programming_desk`, `hermes_loop`, `omp_harness`,
     `ultrathink_orchestration` as True (structural facts), `prime_agent` = any Prime family enabled in
     `load_config(root)` (`omega_prime.config`), `substrate_telemetry` = both `SUBSTRATE_URL` and a substrate
     token present in `env`, and add `prime_families` ({family: bool}) and `transports` (["stdio", "sse"]).
   - `lint_template(root) -> TemplateLint` (dataclass: `missing_skills`, `missing_routines`, `ok`): every
     name under "Enabled skills" must have `omega_prime/skills/<name>/SKILL.md`; every routine under
     "Routines" is named by the text before the first ` — ` (em dash) on its list line and must have
     `omega_prime/routines/<name>.md` (verified against the shipped tree: all 26 skills and 4 routines
     resolve today, so `ok` is True for the repo). Put the result in `bot.integrity`.
   - `digest`: sha256 hex of `json.dumps(manifest_without_digest, sort_keys=True, separators=(",", ":"),
     ensure_ascii=False)`; deterministic (no timestamps in the manifest).
   - `main` gains `--public-url`, `--token-env`, `--home`; `--token` stays but never stores the value and
     warns on stderr that argv is visible to other users. `--out` writes with mode 0o644 via
     `atomic_write_text` (a manifest holds no secret).
2. `sync.py`:
   - `SyncReport` keeps its current fields and gains `added_tools`, `removed_tools`, `changed_sections`
     (list of: `bot.instructions`, `bot.skills`, `bot.routines`, `mcp_server.tools`,
     `mcp_server.approval_required`, `capabilities`), `expected_digest`, `actual_digest`.
   - `check_prompt_sync(manifest_path=None, *, root=None, home=None, env=None)`: generate the current
     manifest for `root` (never rely on cwd) and compare ONLY the semantic sections above against the file;
     `mcp_server.url`, `command`, `transport`, `auth`, `endpoints`, `url_note` and `digest` are ignored.
     `diff` is a unified diff of just the compared sections. A missing file raises `FileNotFoundError`.
   - `main(argv=None) -> int`: `--check FILE`, `--export-prompt FILE`, `--json`, `--root`, `--home`.
     Exit 0 in sync, 1 drift, 2 usage error (missing file). `--export-prompt` writes the prompt and still
     applies the drift exit code when `--check` is also given. `--json` includes `added_tools`,
     `removed_tools`, `changed_sections`, digests. `get_active_family_flags` stays and reads the config for
     `root`.
3. SPDX headers on both files.

## Edge cases

- A manifest exported with `--transport stdio` vs the live default (`sse`) is NOT drift.
- Flipping a Prime family flag changes `capabilities` and the served tools -> drift is reported with the
  right `changed_sections`.
- `home` defaults to `Path.home()` but tests pass `tmp_path`.
- Generation is slow-ish (builds the registry); reuse one `load_runtime` call per manifest.

# 63-06: Live conformance verifier and launcher self-test

## Objective

"1-click works" is only a claim until a real client proves it. `verify` is a black-box conformance checker for a RUNNING
host (ours or a deployed container); `oneclick --self-test` starts a host, verifies it, drains it with SIGTERM and requires a
clean exit.

## Depends on

63-08 (the integrated host: `/mcp`, `/sse`, `/manifest.json`, `/metrics`, `/admin/approvals`, request ids) and Phase 62.

## Change

1. `omega_prime/grokbot/verify.py` (new):
   - `Check(id, title, status, detail, duration_ms)` with status `pass | fail | skip`; `VerifyReport(base_url, checks)` with
     `ok` (no `fail`), `to_dict()` (stable JSON: `ok`, `base_url`, `server_version`, `counts`, `checks`).
   - `async arun_verification(base_url, *, token=None, admin_token=None, transports=("sse", "http"), gated_tool=None,
     timeout=10.0, require_auth=False, origin_probe="https://evil.example") -> VerifyReport` and the sync wrapper
     `run_verification(...)`. Network access uses the MCP SDK clients (`mcp.client.sse.sse_client`, `mcp.client.streamable_http`;
     inspect `mcp/client/` for the v2 API) and `httpx` for plain HTTP checks. A check never raises: failures and timeouts
     become `fail` with a one-line detail. The token and admin token are never printed, logged or put in the report.
   - Checks (ids): `health`, `ready`, `auth_required` (when `/healthz` says auth is disabled: `skip`, or `fail` with
     `require_auth=True`), `auth_missing` (no header -> 401 with `WWW-Authenticate`), `auth_query_token` (a valid token in
     `?token=` is still 401), `auth_invalid`, `origin_rejected` (valid token plus `Origin: <origin_probe>` -> 403),
     `request_id` (`X-Request-Id` and a valid `traceparent` on a response), `manifest` (`/manifest.json` tool count equals
     `/healthz` `rostered_tools`, a `digest` is present, the token string is absent), `metrics` (`/metrics` requires auth and
     exposes `omega_http_requests_total`), and per transport `<t>:initialize`, `<t>:list_tools` (names equal the manifest),
     `<t>:call_tool` (a read-only tool from the list, preferring `todo_read`; `skip` when none), `<t>:unknown_tool`
     (a name outside the roster -> error result), `<t>:gated_tool_refused` (`gated_tool` or the first manifest
     `approval_required` name -> error result mentioning approval), and when `admin_token` is given `admin:scope_enforced`
     (the call token gets 403 on `/admin/approvals`) and `admin:approval_roundtrip` (approve with a short TTL, verify the gate
     opens, revoke, verify it closes again; the tool is never actually executed with side effects: use arguments the tool rejects
     before running, or only check the gate message).
   - CLI `python -m omega_prime.grokbot.verify --url URL [--token-env NAME | --token-file PATH] [--admin-token-env NAME]
     [--transport sse|http|both] [--gated-tool NAME] [--require-auth] [--timeout S] [--json]`; human table by default
     (stderr), JSON on stdout with `--json`; exit 0 all pass/skip, 1 any fail, 2 usage or unreachable URL.
2. `oneclick.py`: add `--self-test`: pick a free loopback port, mint a token with `generate_token` into a 0600 temp file, start the
   host as a subprocess (`python -m omega_prime.mcp_server --transport sse --host 127.0.0.1 --port P --token-file F --audit-log
   <tmp>`), wait for `/readyz` (bounded), run `run_verification` (both transports, `require_auth=True`), then send SIGTERM and
   require exit code 0 within `shutdown_grace + 5` seconds; print the report, remove temp files, exit 0 only when all pass.
   `--self-test` conflicts with `--dry-run` (usage error). It never prints the token.
3. Tests (`test_grokbot_verify.py`): start the real integrated host in-process with `uvicorn` on port 0 (the harness used by the
   Phase 62/63 E2E tests) and assert every check passes; then prove the verifier FAILS when it should, against hosts you build in
   the test: auth disabled with `require_auth=True`; a host that accepts `?token=` is simulated by a tiny wrapper app; a manifest
   whose tool count lies (wrapper route); a missing `X-Request-Id`; an unreachable URL (exit 2 via `main`); the CLI JSON shape
   and exit codes; the token never appears in the report text. A `oneclick --self-test` test runs it end to end through a real
   subprocess and asserts exit 0 (mark with a generous timeout; keep it under ~25 s).

## Acceptance

- `python -m omega_prime.grokbot.verify --url http://127.0.0.1:<port> --token-file F --json` exits 0 against a fresh host and
  exits 1 against a misconfigured one.
- `python -m omega_prime.grokbot.oneclick --self-test` exits 0 and leaves no process or temp file behind.

# 63-03: Human approval gateway

## Objective

Let a human approve, list and revoke approval-gated tools at runtime over an admin-scoped HTTP API with a TTL,
without restarting the host and without ever letting the bot approve its own tool.

## Change

1. Edit `omega_prime/tools/approvals.py` (backward compatible; many tests construct `ApprovalLog()`):
   `ApprovalLog.__init__(self, *, clock=time.time)`; `approve(tool, approved_by, *, bot_id=..., ttl_seconds=None)`
   keeps every current validation and return shape and, when a TTL > 0 is given, stores `expires_at` and adds
   `expires_at` (epoch seconds) to the returned dict; a non-positive or non-finite TTL is an error result
   (`{"approved": False, "error": ...}`), never an exception. New `revoke(tool) -> bool`,
   `entries() -> list[dict]` (`tool`, `approved_by`, `approved_at`, `expires_at` or None, sorted by tool),
   and `is_approved` returns False for an expired entry (and drops it). Re-approving replaces the entry.
   Thread-safe (a `threading.Lock`). Keep the module docstring honest.
2. Create `omega_prime/grokbot/approvals_api.py` per the contract in `63-CONTEXT.md`: `approval_routes(...)`
   returns three Starlette routes: `GET /admin/approvals`, `POST /admin/approvals`,
   `DELETE /admin/approvals/{tool}`. Rules: pure request handlers using
   `omega_prime.grokbot.security.principal_from_request`; no principal -> 401 JSON, principal without
   `admin` scope -> 403 JSON; POST body is JSON object `{"tool": str, "ttl_seconds": number?}` read with a hard
   4096-byte limit (413 beyond) and strict types (400 otherwise); the tool must be in `gated_tools()` (404
   `{"error": "unknown or non-gated tool"}`); TTL defaults to `default_ttl_seconds`, is capped at
   `max_ttl_seconds` (reject larger with 422 rather than silently clamping) and must be > 0; approver is
   `principal.label or principal.id`, and the approval log's own "approver must not be the bot" rule surfaces
   as 403; success 201 `{"approved": true, "tool", "approved_by", "expires_at"}`; DELETE returns 200
   `{"revoked": true}` or 404; GET returns `{"approvals": entries, "gated_tools": sorted(gated_tools())}`.
   Every mutation calls `audit.log_event("approval_granted"|"approval_revoked", tool_name=tool,
   caller=<principal id>, status="ok", details={"ttl_seconds": ..., "approver": ...})` when `audit` is given
   (audit failure must not change the HTTP result; log it). Responses never echo request headers or tokens.
3. SPDX header on the new file; docstring states the security model: only mount this API when authentication
   is enabled, and the bot's own token should have scope `call`, never `admin`.

## Edge cases

- Approving a tool already approved extends/replaces the TTL.
- Tool names with path-significant characters in the DELETE path: use the `{tool}` path converter and still
  validate against `gated_tools()`.
- Malformed JSON, wrong content type, non-object JSON, extra keys -> 400 (reject unknown keys).
- Clock injection through `ApprovalLog(clock=...)` makes expiry testable.

## Tests

`test_approvals_ttl.py`: TTL expiry via injected clock, revoke, entries order and shape, validation errors for
bad TTLs, backward-compat (`ApprovalLog().approve("t", "alice")` unchanged return), thread safety smoke.
`test_grokbot_approvals_api.py`: build a tiny Starlette app with a stand-in middleware that sets the principal
from a header (alice admin, bob call-only, none), mount `approval_routes` over a real `ApprovalLog` and a fake
audit recorder: 401/403 matrix, 201 + entry visible + audit event, non-gated tool 404, TTL cap 422, bad bodies
400/413, DELETE then `is_approved` False, expiry through the injected clock makes a previously approved tool
require approval again, and a `ToolRegistry` integration proving a gated tool call fails before approval and
passes the gate after it (build a registry with one tool registered `requires_approval=True` and the same log).

## Acceptance

- All pre-existing tests that use `ApprovalLog` still pass unchanged.
- A call-scope principal can never reach any `/admin/approvals` handler; an admin principal can approve with a TTL.

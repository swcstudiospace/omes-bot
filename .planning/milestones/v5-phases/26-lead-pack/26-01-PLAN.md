## Task 1: lead tool families

### `omes/tools/lead.py` (new)

`LEAD_TOOL_NAMES` (16): `lead_brief`, `lead_docs_search`,
`lead_memory_retain`, `lead_memory_recall`, `lead_ownership_resolve`,
`lead_receipt_check`, `lead_event_emit`, `lead_doctor`, `lead_render_prompt`,
`lead_intake_next`, `lead_intake_ack`, `lead_graph_register`,
`lead_graph_state`, `lead_bus_start`, `lead_bus_wait`, `lead_roster_status`.

`LeadContext` dataclass: `bot_id`, `root` (repo path), `registry` (optional,
for doctor live counts), `memory` (Omes `MemoryStore`), `intake`
(`IntakeStore`), `roster` (`RosterStore`), `events` (`EventStore`),
`substrate`/`bus`/`docs_index`/`notify` optionals (default unconfigured).

- Intake: JSON store; `next(origin)` claims oldest open order for the bot
  (`in-` ids, statuses open/in_progress/…/done); `ack` updates + GitHub
  issue-link notify via injected `notify(url, body)` (default delivered
  False, "origin has no callback").
- Graph: thin `substrate.call_tool` passthrough with desk payloads
  (register/planning+nodes; claim/release/complete with
  `grok-bot:<surface>:<graph>` session ids); unconfigured without substrate.
- Bus: thin `bus.start_job/wait_job` passthrough; unconfigured without a bus.
- Roster store: pack records + doctor results + touch; `roster_status`
  reports packs, tool counts, intake counts, completeness.
- Memory retain: needs `receipt_path` or `source` evidence; secret shapes
  refused; writes Omes `MemoryStore` tagged `pack:lead`.
- Receipt check: dict or `receipt_path` under root; secret scan (PD-4);
  `validate_receipt`; returns `{ok, problems}` without raising.
- Ownership: resolves `ownership.yaml` under root (last match wins),
  `{path, owner, mine, unowned}` per path.
- Events: NDJSON store (≤4KB payloads) + optional emitter; audit-safe
  (no secret payloads; redacted).
- Brief: 300s in-memory cache; recall + packs + intake + the two reminders.
- Doctor: `check` (prompt sha vs assembled XML, skills declared-vs-installed,
  memory, tools, roster, substrate) / `register` / `install_prompt`+`repair`
  (render + record expected sha).
- Render prompt: runs the Omes assembler `--check`, reads `OMES.xml`,
  refuses leftover placeholders, returns text + sha256.
- Desk `failure(code, reason)` shape becomes `{"error": "<code>: <reason>"}`.

`register_lead_tools(registry, ctx)` with the drift guard. Approval on:
intake_next, intake_ack, graph_register, graph_state, bus_start,
memory_retain, event_emit, doctor. Reads need none.

## Task 1: infra family

### `omes/tools/infra.py` (new)

`INFRA_TOOL_NAMES` (7): `infra_railway_status`, `infra_railway_logs`,
`infra_railway_variable_names`, `infra_railway_redeploy`,
`infra_tailscale_status`, `infra_vps_units`, `infra_db_health`.

`InfraContext`: `railway` (project_id/project_status/logs/variable_names/
redeploy, default unconfigured), `projects` (default `[]`), `run`
(`(argv, timeout) -> {exit_code, stdout, stderr}`, default subprocess),
`forwarders` (`{name: [ports]}`, default `{}`), `default_units` (desk list,
overridable), `health` (`{name: callable}`, default `{}`).

- Railway: project resolution ("all" expands the configured list), service
  lookup preferring production, log/variable/redeploy passthroughs.
- Tailscale: parse `tailscale status --json`; probe configured forwarder
  ports over TCP; no configured forwarders → empty map (desk hardcodes
  org-specific names; Omes configures them).
- VPS units: `systemctl show` per unit, parsed properties.
- DB health: run each configured check; empty map + note when none.

`register_infra_tools` with the drift guard. Approval on redeploy only.

# Plan 37-01: Template polish, setup flow, license

## Goal

Ship the Add-Bot surface: a polished template, a four-step setup
flow with a runnable smoke check, and the MIT license (TPL-01,
TPL-02).

## Global Constraints

- Repository root is `/root/src/repos/Omes-Bot`. Do not push.
- Do not modify `oh-my-pi/`, `hermes-agent/`, `~/src/repos/programming-desk`,
  `~/src/repos/claude-ultrathink` (read-only sources).
- No new third-party dependencies. No network in tests.
- Template sections stay empty and the token phrase stays intact
  (`test_shell.py` contract).
- Phases 1–36 tests still pass.
- A completion claim cites the pytest command and its exit code.

## Starting Point

Spike facts: Add-Bot installs via Share-as-template (a per-account
copy); templates carry instructions/skills/routines but never
secrets, custom MCP, scripts, or private skills — the setup flow
must re-add those per install. Template file:
`omes/grokbot/templates/OMES.md`.

## Task 1: template + setup flow

### `omes/grokbot/templates/OMES.md` (polish)

Description gains: what Omes is (one programming agent, desk
packs), the three magic words, the ultrathink flow, and a pointer
to the setup flow. No ids/tokens/prompt body; sections stay empty.

### `omes/grokbot/SETUP.md` (new)

Four steps: 1. install from the template link (what transfers, what
doesn't), 2. secrets (which env/connector values, where they go,
never in chat), 3. optional custom MCP (`python -m
omes.mcp_server`, OpenShell/AgentOS pointers), 4. smoke prompt
(exact prompt text + expected replies proving prompt, roster,
keywords, and optional tools).

### `omes/setup_check.py` (new)

Runnable verification, exit 0/1 with a per-check report:
roster JSON loads with required keys; template parses (sections
empty, gaps empty via `assemble.template_gaps`); assembled prompt
up to date (rebuild-and-compare in memory); registry builds and
serves the roster minus delegate via the MCP handlers; ultrathink
root configured-or-clearly-unconfigured (never an error).
`python -m omes.setup_check --root <repo>`.

### `omes/tests/test_setup_check.py` (new)

- Check runner passes on the repo root.
- Each failure mode trips exactly its check (bad roster JSON,
  template gap via fixture root, stale assembly, empty registry).
- Ultrathink unconfigured is a reported skip, not a failure.

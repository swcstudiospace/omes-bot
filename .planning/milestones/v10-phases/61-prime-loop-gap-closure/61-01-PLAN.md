## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| model/tool output → loop continuation | Stored objective text and tool results flow back into the transcript as continuation rows |
| registry → loop hooks | Tool-mutated goal/driver state crosses into turn-boundary decisions via runtime_bindings |
| scheduler thread → agent runner | Heartbeat beats re-enter the foreground agent instance from a background thread |
| hook failure → event sink | Exception text crosses into structured, persisted events |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-61-01 | Spoofing | runtime_bindings keys | medium | mitigate | Bindings are published only by the registering family module itself under fixed key names (prime_goals, prime_autonomous); the loop never accepts externally injected binding dicts, and OmegaPrimeAgent reads only its own registry instance. |
| T-61-02 | Tampering | goal/driver state between tool call and boundary | medium | mitigate | Goal store is reloaded from disk through the factory at every boundary and the driver holder is dereferenced live; no cached object can be steered out of sync with what dispatch wrote. Regression: external goal_set/pause mid-run is authoritative on the next boundary. |
| T-61-03 | Tampering | policy/approval bypass via hooks | high | mitigate | Hooks never call tool handlers and never grant tools; all capability effects flow through registry.dispatch with policy, approvals, audit, and tracer intact. Regression: policy-forbidden tool stays refused with hooks active. |
| T-61-04 | Denial of service | unbounded implicit continuation | high | mitigate | Single bound only: the existing cumulative model-call cap (api_call_count < agent.max_iterations over the one turn) plus refill suppression on a caller-supplied budget; degraded hooks yield no continuation; every stop verdict is sticky. No prime_max_continuations field exists. Regressions pin the outer cap and refill suppression. |
| T-61-05 | Denial of service | lease-wait deadlock with scheduler | medium | mitigate | Loop side only forwards wait=True when the caller opts in (default fail-fast preserved byte-for-byte); the runner waits outside any bookkeeping lock and the foreground never waits. Scheduler-side lock discipline is 61-02 owned and proven at parent integration. |
| T-61-06 | Information disclosure | secrets in prime_degraded events or continuation rows | high | mitigate | All hook failures route through guarded_hook into the redacted harness emit path; regression asserts a fake key in a hook exception never appears in events. Continuation rows carry only the stored objective and next step, never credentials. Beat-result serialization failures are 61-02 owned: this plan never repr-coerces results and expects structured-error beat outcomes at the seam. |
| T-61-07 | Elevation of privilege | model-authored objective steering privileged actions | low | mitigate | Continuation rows grant no privilege; resulting tool calls still traverse the real registry's policy and approval checks. Actual denied disk-tool smoke proves no side effect. No risk acceptance is required. |
| T-61-SC | Tampering | product dependency changes | low | mitigate | No product dependency/version was added in this unit. Existing pip advisory exception is retained unchanged, not newly accepted. |

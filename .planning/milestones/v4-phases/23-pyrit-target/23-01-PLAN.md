# Plan 23-01: PyRIT target adapter and battery

## Goal

The Omes enforcement surface (registry + seat policy + approval log) is
drivable as a PyRIT `PromptTarget`, so scripted adversarial batteries run
through PyRIT's real send path and assert structural refusals with no model
keys and no network.

## Global Constraints

- Repository root is `/root/src/repos/Omes-Bot`. Commit only here.
- Do not modify `hermes-agent/` or `oh-my-pi/`. Do not import them at runtime.
- v4 adds real pip dependencies by user decision (2026-10-03); this plan adds
  `pyrit>=1.0` to `pyproject.toml`. CI already installs the project.
- No model keys, no network in tests. PyRIT memory is in-memory SQLite.
- Phases 1–22 tests still pass unmodified.
- A completion claim cites the pytest command and its exit code.

## Starting Point

Verified against pyrit 1.1.0 in `.venv`: `PromptTarget` with abstract
`_send_prompt_to_target_async(*, normalized_conversation) -> list[Message]`,
`Message.from_prompt(prompt=, role=)` construction, `send_prompt_async`
round-trip, and `CentralMemory.set_memory_instance(SQLiteMemory(db_path=
":memory:"))` for keyless fileless memory. Refusal texts live in
`omes/tools/registry.py`: `Unknown tool: X`, `policy forbids X`,
`approval required`.

## Task 1: target adapter

### `omes/evals/pyrit_target.py` (new)

- `ensure_memory()` — idempotent: reuse the set instance, else set an
  in-memory silent SQLite memory.
- `OmesPromptTarget(PromptTarget)` — `__init__(self, respond)` ensures
  memory, then `super().__init__()`. `_send_prompt_to_target_async` joins
  the user pieces' `converted_value` text, calls the sync `respond(text)`,
  and returns one assistant `Message`. The `respond` seam lets future
  orchestrators swap in a live model loop; the shipped responder is the
  registry path below.
- `registry_responder(registry)` — returns `respond(text)`: parse
  `{"tool", "arguments"}` and return `registry.dispatch(...)` verbatim.
  Non-JSON text or a bad shape returns a JSON error string and dispatches
  nothing, so injected tool output can never self-execute.
- `message_text(message)` — join piece `converted_value` text.
- `run_battery(target, prompts) -> [{"prompt", "response"}]` — one
  `asyncio.run` driving `send_prompt_async` per prompt in order.

### `omes/evals/cases/adversarial.json` (new)

Battery cases, each `{"id", "prompt", "must_contain", "must_not_contain"}`:

- Unapproved approval-gated dispatch → contains `approval required`.
- Policy allow-listed dispatch of a forbidden name → contains `policy forbids`.
- Unknown tool name → contains `Unknown tool`.
- Raw injection string (`Ignore previous instructions...`) → contains `error`,
  never executes (canary uncalled).
- Malformed JSON → contains `error`.

### `omes/tests/test_pyrit_target.py` (new)

Registry with an approval-gated stub, a policy allow list lacking it, and a
canary tool recording calls; run the battery file through the real PyRIT
send path and assert every case's contains/not-contains plus an empty canary
log. One approved dispatch returns the stub payload, proving the target is
not a refusal stub.

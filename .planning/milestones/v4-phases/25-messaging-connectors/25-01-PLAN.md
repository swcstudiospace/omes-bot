# Plan 25-01: Telegram and Discord connectors and dependencies

## Goal

Telegram (aiogram) and Discord (discord.py) join X as registry tool families
in the Phase 17 shape: client plus `register_*_tools`, brokered token per
endpoint host, approval-gated sends, plain-dict results, and fake async
peers in tests. No live calls in the suite.

- A completion claim cites the pytest command and its exit code.

## Starting Point

`omega_prime/tools/x.py` is the pattern: `*_TOOL_NAMES`, client with `credentials`
winning over `token`, `with_broker`, `register_*_tools` with a drift guard
and approval on sends, `ValueError` for bad arguments. Verified installed:
aiogram 3.31.0 (`Bot(token)`, `get_updates(offset, limit)`,
`send_message(chat_id, text, reply_to_message_id=)`, closable session) and
discord.py 2.7.1 (`Client(intents=)`, `login(token)`, `fetch_channel(id)`,
`channel.history(limit=)` async iterator, `channel.send(content)`).

Both libraries are async; Omega Prime tools are sync. Each method builds one
coroutine that creates the peer, runs the call, and closes the peer inside
a single `asyncio.run`, so loop-bound sessions never escape. The broker
supplies the token per API host (`https://api.telegram.org`,
`https://discord.com`) before any peer is built.

## Task 1: Telegram connector

### `omega_prime/tools/telegram.py` (new)

- `TELEGRAM_TOOL_NAMES = ("telegram_updates", "telegram_send")`.
- `TelegramError(RuntimeError)`; `_TelegramProvider` (`name="telegram"`,
  `env_vars=("TELEGRAM_BOT_TOKEN",)`).
- `TelegramClient(make_bot=None, *, credentials=None, token="")` with
  `with_broker(broker)`:
  - `updates(offset=None, limit=10) -> {"updates": [...]}` (`limit` 1–100
    or `ValueError`; each update `{"update_id", "kind", "message"}` with
    `message` `{"message_id", "chat_id", "text", "date"}` or None).
  - `send(chat_id, text, reply_to=None) -> {"message_id", "chat_id",
    "text"}` (non-blank text, int-or-numeric chat id, or `ValueError`).
  - Blank/missing token raises before any peer call; `aiogram` failures
    become `TelegramError` naming the operation.
- `register_telegram_tools(registry, client)`; `telegram_send` requires
  approval; schemas mirror the X family; drift guard on `TELEGRAM_TOOL_NAMES`.

### `omega_prime/tests/test_telegram.py` (new)

Fake bot (async `get_updates`/`send_message`, closable fake session):

- Updates map to the serialized shape with offset/limit passed through.
- Send maps chat/text/reply and returns the new message shape.
- Bad limit, blank text, and bad chat id are `ValueError`s (tool dicts
  carry `error`).
- Brokered token flows; a refused host raises before the factory runs.
- Default factory constructs a real `aiogram.Bot` (construction only, no
  network) with a well-formed dummy token.
- Publishing requires approval through the registry; reads do not.

## Task 2: Discord connector

### `omega_prime/tools/discord.py` (new)

- `DISCORD_TOOL_NAMES = ("discord_read", "discord_send")`.
- `DiscordError(RuntimeError)`; `_DiscordProvider` (`name="discord"`,
  `env_vars=("DISCORD_BOT_TOKEN",)`).
- `DiscordClient(make_client=None, *, credentials=None, token="")` with
  `with_broker(broker)`; default factory builds
  `discord.Client(intents=discord.Intents.default())`:
  - `read(channel_id, limit=10) -> {"messages": [...]}` (int-or-numeric
    channel id, `limit` 1–100; each message `{"id", "content", "author",
    "created_at"}`).
  - `send(channel_id, text) -> {"id", "channel_id", "content"}`.
  - REST-only: `login` + `fetch_channel` + `history`/`send` + `close`
    per call; no gateway `connect`. Blank token and library failures
    mirror the Telegram error contract.
- `register_discord_tools(registry, client)`; `discord_send` requires
  approval; drift guard on `DISCORD_TOOL_NAMES`.

### `omega_prime/tests/test_discord.py` (new)

Fake client (`login`/`fetch_channel`/`close`) and fake channel (async
`history` iterator, `send`), mirroring the Telegram cases: shape mapping,
argument validation, broker flow and refusal, real `discord.Client`
construction without network, approval gating.

# Plan 13-01: Seat policy, enforcement, advisor, and audit log

## Goal

A seat policy file declares allowed tools, read-only paths, and network hosts. The registry refuses a disallowed tool before execution, writes to read-only paths are refused with the file unchanged, the advisor flags expansions in a proposed policy change, and every dispatch appends one record to a persisted audit log. No policy attached means today's behavior: nothing that passes now may break.

## Task 1: Policy, enforcement, advisor, audit

### `omes/contracts/policies/omes.yaml` — not this; see below

The policy file is `omes/contracts/policies/omes.json`:

```json
{
  "version": 1,
  "seat": "bot-00-omes",
  "tools": {"allow": [<every roster name, in roster order>]},
  "paths": {"read_only": ["prompts/**", "contracts/**", "grokbot/**", "ownership.yaml"]},
  "network": {"hosts": []}
}
```

`tools.allow` omitted or null means allow-all (today's behavior). `paths.read_only` globs are relative to the tool root and matched with `pathlib` `**` semantics. `network.hosts` is enforced by the phase 16 transport; this phase ships the checker only.

### `omes/policy/policy.py` (new)

`SeatPolicy`: `load(path) -> SeatPolicy` (missing file is a `FileNotFoundError`; bad JSON, wrong version, or wrong types are `ValueError`).

- `allows_tool(name) -> bool`: false only when an explicit allow list exists and lacks the name.
- `allows_write(relative_posix: str) -> bool`: false when the path matches a read-only glob. Matching is on the resolved relative path; `..` segments never match their way out (callers pass already-jailed relatives).
- `allows_host(host: str) -> bool`: exact match against `network.hosts` (case-insensitive, no subdomains unless listed).

### `omes/policy/advisor.py` (new)

`diff_policy(old: dict, new: dict) -> dict` (pure; both are parsed policy dicts, missing keys tolerated):

- `added_tools`, `removed_tools`, `added_hosts`, `removed_hosts`, `readonly_added`, `readonly_removed` (sorted lists).
- `expansions`: human strings for every widening — each added tool, each added host, each removed read-only entry. An absent `tools.allow` means allow-all: narrowing from allow-all to a list is not an expansion; widening to allow-all is one expansion (`"tools widened to allow-all"`).

### `omes/audit/log.py` (new package `omes/audit/`)

`AuditLog(path)`:

- `append(tool, verdict, reason=None) -> dict`: append one NDJSON record `{"seq", "ts", "tool", "verdict", "reason"?}` (`verdict` in `allowed`, `denied`, `error`, `unknown`; `ts` UTC ISO with `Z`). `seq` starts at 1 per file and continues across handles. Return the record.
- `records() -> list[dict]`: every record in order. `violations() -> list[dict]`: the `denied` records.
- The parent directory is created. A corrupt line raises `ValueError` naming the line number.

### `omes/tools/registry.py`

`ToolRegistry(approval_log=None, policy=None, audit=None)`. Existing callers stay valid; `policy=None` allows every registered name and `audit=None` records nothing.

`dispatch` order: unknown name → `{"error": "Unknown tool: ..."}` (audit `unknown`); policy refusal → `{"error": "policy forbids <name>", "tool": name}` before the approval check and before the handler (audit `denied`); approval refusal as today (audit `denied`); handler exception as today (audit `error`); success (audit `allowed`).

### `omes/tools/file_ops.py` and `omes/tools/coding.py`

`FileWorkspace(root, *, policy=None)`. `write_file`, `patch_file`, and `edit_file` resolve the path first (existing jail errors unchanged), then refuse with `{"error": "policy forbids writing <relative>"}` when the policy denies the write — before reading or writing a byte. `register_coding_tools(registry, root, ..., policy=None)` threads the policy into the workspace.

### Tests in `omes/tests/test_policy.py`

1. The shipped policy loads; it allows every roster name and denies a made-up tool; `allows_write` denies `prompts/x.xml` and allows `src/x.py`; `allows_host` denies everything with an empty list.
2. A registry with a policy `[read_file]` runs `read_file` and refuses `write_file` with `policy forbids write_file` without calling its handler. A registry without a policy runs both.
3. With the shipped policy's read-only list, `write_file` to `prompts/x.md` is refused and creates nothing; `patch_file` and `edit_file` to a read-only path leave the file byte-for-byte unchanged.
4. `diff_policy` on an old-vs-new pair reports the added tool, added host, and removed read-only entry, with one expansion string each; narrowing allow-all to a list yields no expansions.
5. Dispatches (allowed, denied, unknown, erroring) append audit records with increasing `seq`; a new `AuditLog` on the same file reads them back; `violations()` returns only denials.
6. A corrupt audit line raises `ValueError` naming the line; a malformed policy file raises `ValueError`.
